# Память диалогов

Aigram автоматически собирает фактический профиль владельца: подтверждённые сведения, интересы, бытовые привычки и содержательные предпочтения из настоящих исходящих сообщений. Профиль используется во всех диалогах. Отдельные сводки бесед сохраняют отношения, важные события и частные договорённости. Стиль письма, тон, привычки использования эмодзи и инструкции модели в автоматическую память не включаются. Порции постепенно охватывают доступную историю.

Выбранный стиль беседы передаётся отдельным блоком системных инструкций после фактического контекста. Необязательные наблюдения о пунктуации и словах владельца берутся из ручных исходящих сообщений вне банка памяти и подчиняются выбранному стилю. У именованных стилей инструкции также отделены от дополнительных указаний беседы.

Разделение фактов и правил поведения соответствует [подходу LangMem](https://langchain-ai.github.io/langmem/concepts/conceptual_guide/). Существующий [Spring AI ChatMemory](https://docs.spring.io/spring-ai/reference/api/chat-memory.html) продолжает собирать окно недавних сообщений. Для локального профиля дополнительный фреймворк памяти или внешняя база не требуются.

## Файлы

В каталоге данных приложения `%LOCALAPPDATA%/Aigram`:

```text
memory/
  MEMORY.md                      ручные заметки + профиль активного аккаунта
  <telegramAccountId>/
    PROFILE.md                   автоматический профиль аккаунта
    state.json                   курсоры и состояние обработки
    <chatId>/
      MEMORY.md                  ваши заметки + автоматическая сводка
```

Общий файл создаётся сразу при запуске и содержит ручные заметки плюс автоматический профиль активного аккаунта. Профиль сохраняется также в `memory/<telegramAccountId>/PROFILE.md` и восстанавливается при переключении аккаунтов. Сведения о собеседниках остаются в памяти чатов. Папки бесед создаются для используемых чатов, выбранных источников профиля и ручных запросов.

В файле беседы автоматическая часть находится между `<!-- boltunya:auto:start -->` и `<!-- boltunya:auto:end -->`. Всё снаружи — ручные заметки. Их можно редактировать в приложении или обычном редакторе. Фоновое обновление сохраняет ручную часть; конфликт с одновременным редактированием не перезаписывает файл, а оставляет порцию для повторной обработки.

У фактической автоматической части есть маркер версии. Старые сводки могут содержать указания о манере, поэтому до пересбора исключаются из генерации и входных данных суммаризации. Их текст остаётся доступен для просмотра, ручные заметки сохраняются. Пересбор назначается только подходящим беседам, которые уже выбраны работником; обновление не обходит весь аккаунт. Успешные порции заменяют старую автоматическую часть и обновляют её версию.

## Обработка истории

Через 30 секунд после запуска работник проверяет восстановление Telegram. По умолчанию автоматический и общий сбор обрабатывают только беседы, где включён ИИ и разрешена память. В настройках область можно явно расширить до всех разрешённых бесед; запреты памяти и исключение каналов сохраняются. Входящие и исходящие сообщения других чатов не добавляют их в источники. Явный ручной сбор одной беседы — разовый запрос: он может завершить доступную историю при выключенном ИИ, но не подписывает чат на новые сообщения. Завершённые неизменившиеся чаты пропускаются. В обработке участвуют только беседы из основного списка Telegram или архива, а не все объекты кеша TDLib.

Первый проход начинает с последних сообщений, чтобы полезная память появилась быстро. Затем отдельный курсор движется к началу беседы. За один проход берётся до 100 сообщений, из которых выбирается ограниченная по размеру порция. Не вошедшие сообщения остаются перед курсором и попадают в следующий проход. Работник проверяет очередь каждые 15 секунд; эта проверка не запускает сбор раньше настроенного интервала. Работа распределяется между беседами и возобновляется после перезапуска.

Входящие и исходящие сообщения отмечают диалог как изменившийся. После глубокого разбора обновляется только новая часть. Большая пачка новых сообщений также обрабатывается постранично: верхний ID фиксируется отдельно, а контрольная точка продвигается только после завершения всей пачки. Новые сообщения, пришедшие во время обработки, остаются ожидающими.

По умолчанию автоматический сбор запускается каждые **6 часов** для каждой беседы. В настройках есть переключатель фоновой памяти и выбор интервала; API допускает 1–168 часов. Этот интервал соблюдают и новые сообщения, и незавершённый глубокий разбор. Время последней автоматической попытки сохраняется вместе с контрольной точкой, включая неудачные попытки: перезапуск приложения и ошибка генерации не запускают новый автоматический проход через несколько минут. При обновлении существующие контрольные точки сохраняют прежнее время обновления. Явный ручной сбор обходит интервал и продолжает обработку порций до завершения или отмены. Отдельная отметка времени для свежих сообщений не позволяет старой истории бесконечно откладывать их обработку.

Ответы, черновики и память используют общую очередь. Добавление задачи не отменяет выполняющийся сбор. При ожидании локального ресурса то же событие памяти возвращается в очередь с прежним ID и контрольной точкой. Порции памяти выполняются последовательно для безопасного объединения общего профиля. Последние 10 секунд переписки откладываются, чтобы успеть отметить автоматические исходящие сообщения. Для памяти предусмотрен собственный переключатель.

Используется настроенный маршрут задач памяти либо основная модель и подключение, если отдельный маршрут не выбран. Модели автоматически не скачиваются. Локальный сбор ожидает доступности Ollama и выбранной модели. После ошибки автоматический сбор ждёт настроенный интервал; ручной запуск позволяет повторить попытку раньше. Состояние остаётся доступно в настройках и событиях.

Общий профиль получает только источники `speaker=owner`: сообщения собеседников и известные автоответы удаляются до обращения к модели. ID автоматических сообщений больше не обрезаются после 5000 записей и сохраняются при выходе из Telegram. Старые ответы, для которых ранее не сохранился ID, достоверно распознать нельзя. Чужие цитаты и шутки не должны превращаться в факты; профиль остаётся вероятностной сводкой модели. Ручные заметки имеют приоритет. Профиль и сводка беседы сохраняются до продвижения курсора; ошибка или конфликт оставляет порцию для повторного прохода. После обновления старые завершённые чаты один раз перечитываются для построения профиля.

Незавершённый ручной сбор отключённого чата не запускается автоматически вместе с приложением. Повторный явный запуск продолжает разбор с сохранённого курсора. Отмена ожидающего или выполняющегося сбора также сохраняет отсрочку автоматического запуска, даже если генерация ещё не началась; перезапуск не снимает это ожидание. Новый явный ручной запрос позволяет запустить сбор раньше.

## Использование и управление

- **Настройки → Память**: общие заметки и число отслеживаемых диалогов.
- Параметры общения открывают память выбранной беседы, автоматическую сводку и прогресс сбора.
- **Обновить память** запускает выбранный чат; общий сбор учитывает выбранную область и разрешения памяти.
- **Пересобрать сводку** сохраняет ручные заметки и начинает глубокий разбор заново.
- **Использовать память диалога** управляет его контекстом и сбором; уже собранный общий профиль остаётся доступным.

В обоих окнах памяти действия оформлены компактными кнопками по ширине текста. На узком экране кнопки переносятся и сохраняют размеры при открытии проводника: [память беседы](../resources/memory-dialog-light.png), [общая память](../resources/settings-memory-dark.png), [узкое окно](../resources/memory-actions-narrow-dark.png).

Общие заметки, профиль владельца, заметки беседы и готовая сводка добавляются к недавней истории при автоответах и создании черновиков. Память передаётся как справочные JSON-данные; настройки владельца и свежие реплики важнее исторической сводки. Автоматические исходящие отделяются от настоящих сообщений владельца. Для групп сохраняется идентификатор отправителя, чтобы не объединять участников с одинаковыми именами.

Память — сжатый контекст, не дословный архив и не гарантия точного воспоминания каждой детали. Размер одной сводки ограничен 6000 символами. Порции исходной истории подбираются по бюджету токенов фактической модели с учётом сводок, инструкций и резерва ответа с рассуждениями. Исходные сообщения сохраняются целиком; если одно сообщение не помещается, сбор останавливается без продвижения контрольной точки. Объём памяти в ответах также подбирается по токенам, оставляя место свежим сообщениям и фотографиям. Вложения учитываются в банке памяти по подписям, распознавание фото и речи туда не сохраняется. Подтверждённое удаление сообщения или исключение из контекста сбрасывает сводку затронутого чата и общий автоматически собранный профиль, сохраняя ручные заметки. Это не сбрасывает контрольные точки остальных чатов и не запускает внеочередной глобальный сбор. Файлы остаются в вашем каталоге данных.

## API и проверки

Контракт: `backend/contract/api/schema/api.yaml`. Все маршруты защищены существующей локальной сессией, проверкой Host/Origin:

- `GET/PATCH /api/memory`: общие заметки.
- `POST /api/memory/refresh`: проверка изменившихся используемых диалогов.
- `GET/PATCH/POST /api/memory/{chatId}`: просмотр, изменение заметок и обновление/пересборка.

PATCH принимает текст заметок и `revision`; устаревшая редакция возвращает 409. Пересборка: `{"rebuild":true}`. Настройки: `memoryEnabled`, `memoryIntervalHours`; правило беседы: `useMemory`.

Проверки покрывают глубокую историю из 700 сообщений, восстановление курсоров, большую пачку новых сообщений, расписание во время глубокого разбора, пропуск неактивных и неизменившихся чатов, разделение аккаунтов, сохранение Markdown, конфликты, приоритет ответов, локальный HTTP API и редактор заметок. Необязательный `LiveMemoryTest` использует только уже установленную модель и искусственную переписку; реальным собеседникам ничего не отправляется.

## Принудительный сбор контекста

Кнопка «Собрать контекст» в параметрах общения открытого чата открывает отдельное окно. «Новые сообщения» сохраняет сводку и добавляет историю после контрольной точки. «Вся доступная история» сбрасывает автоматическую сводку и курсоры выбранного чата; ручные заметки сохраняются. Сбор идёт порциями с текущим статусом и числом просмотренных сообщений. Неизвестный общий объём истории не отображается как выдуманный процент.

Ручной запуск отправляет `POST /api/memory/{chatId}` с `immediate: true` и выбранным `rebuild`. Беседа ставится в общую очередь без ожидания часового интервала. Запуск не отменяет сбор другой беседы или выполняющийся ответ. При отключённой памяти её нужно явно включить. Закрытие окна не отменяет задачу.

**Настройки → Память → Общий сбор контекста** обрабатывает беседы, разрешённые выбранной областью сбора и настройками памяти. «Новые сообщения» сохраняет имеющиеся сведения. «Вся доступная история» очищает автоматический профиль и сводки подходящих бесед, сохраняя ручные заметки. Запрос полного прохода — `POST /api/memory/refresh` с `{"rebuild":true,"immediate":true}`. Порции памяти выполняются последовательно в общей очереди.

В шапке личного чата показывается первый активный Telegram username; если его нет, строка отсутствует. Для групп используется кешированное количество участников из обновлений Telegram, без отдельных сетевых запросов на каждый чат. Пока число неизвестно, отображается «Группа». API `Chat` содержит `username` и nullable `memberCount`.


После ручного запуска вместо кнопки сбора в параметрах общения показывается блок с состоянием, числом диалогов в очереди, позицией и количеством обработанных сообщений текущего прохода. Окно можно закрывать и открывать: статус приходит от сервера. Кнопка «Отменить сбор» снимает выбранный проход; незавершённая генерация не записывается, заметки и уже сохранённые сводки остаются. Автоматическая обработка этого диалога возобновляется не раньше настроенного интервала либо после нового ручного запуска. В общем окне отменяются все оставшиеся ручные задачи. API: POST /api/memory/{chatId}/cancel и POST /api/memory/cancel.

Список диалогов отображается порциями по 40, дополнительные строки загружаются при прокрутке вниз с Gravity Loader. Поиск и фильтры работают по полному полученному списку. При смене фильтра отображается скелетон. В превью исходящих сообщений указан «Вы», в группах — короткое имя отправителя. У @тега доступны отдельные кнопки копирования тега и ссылки Telegram.


## Справочник авторов группы

В `memory/<accountId>/<chatId>/PARTICIPANTS.json` хранится краткий справочник наблюдавшихся авторов: ID, отображаемое имя, username Telegram и сведения о давности источника. Данные берутся из поступивших сообщений и истории, уже загружаемой для этой беседы; имена и теги используются из кеша Telegram. Полный список участников не запрашивается, дополнительные истории не скачиваются, описания характеров не генерируются. Старые страницы истории не заменяют данные из более новых сообщений.

Файл ограничен 1000 последними участниками. Модель получает не более 80 записей в пределах бюджета контекста; текст сообщений в этот справочник не записывается. Исключённые источники пропускаются; изменение политики также скрывает прежние записи, если их последнее сообщение-источник исключено. Аккаунты и беседы хранятся раздельно.

## Область сбора

В **Настройки → Память** можно выбрать сбор только для бесед с включённым ИИ (по умолчанию) или для всех разрешённых диалогов, включая беседы без автоответов. Запрет «Использовать память» в отдельном чате сохраняет приоритет. Каналы рассылок не включаются. Настройка `memoryCollectionScope`: `ai-enabled` или `all-allowed`. Общий ручной сбор использует ту же область; отдельный ручной запрос остаётся разовым. Сохранение других настроек не отменяет задания памяти.
