# Архитектура

Electron владеет нативным окном, треем и автозапуском. Он запускает единственный Kotlin-процесс и ожидает `launch.url` в каталоге данных. Kotlin раздаёт статический Next.js export и локальный API. Адрес и секрет никогда не передаются внешним сервисам; после установки cookie секрет удаляется из истории окна.

## Модули

- `desktop/src`: lifecycle `Backend`, `TrayController`, `StartupRegistration`, main и изолированный preload. Нативное перемещение реализовано через `-webkit-app-region: drag`; maximize использует рабочую область Windows, fullscreen отключён.
- `backend/configuration`: Spring Boot, singleton-компоненты и конфигурации интеграций по функциям. Зависимости передаются через единственный конструктор; `ObjectProvider` разрешает ленивые зависимости. `Main` получает `ApplicationRuntime` из servlet-контекста.
- `backend/application`: блокировка профиля, запуск интеграций, координированное завершение. `engine` завершается перед Telegram, чтобы не оставлять локальный Ollama при долгом закрытии TDLib.
- `backend/controller`: реализации восьми generated-интерфейсов Spring MVC и контроллер статического Next.js export. Контроллеры принимают и возвращают generated DTO.
- `backend/component`: бизнес-операции по функциям поверх существующих сервисов. `backend/transformer` содержит stateless extension-функции верхнего уровня для преобразования transport DTO и domain-моделей. Функции вызываются на receiver и не имеют Spring-бина, конструктора или жизненного цикла; универсального адаптера через JSON нет.
- `backend/server`: принудительный loopback и случайный порт, локальная сессия, request filter, ограничение тела и общий обработчик ошибок. Защита и лимиты используют декодированный servlet path, как MVC, включая URL с кодированием и matrix-параметрами. Авторизация выполняется до чтения тела запроса.
- `backend/validation`: Jakarta Validation и правила входных данных/выбора модели. Jackson не преобразует строки в boolean/числа; default-поля generated request DTO сохраняют поведение пропущенных полей, не ослабляя обязательные response DTO.
- `backend/domain`: модели разделены на `chat`, `media`, `telegram`, `memory`, `ai`, `settings`, `events` и `system`, отдельно от generated DTO. Существующее хранение JSON/Markdown сохранено.
- `backend/contract`: единый OpenAPI по функциям, generated Spring API/DTO, Kotlin WebClient, типизированная закрываемая Kotlin-обёртка и TypeScript Fetch SDK. Результаты генерации остаются в `build/` модулей. [Контракт и клиенты](../api-client/ru.md).
- `backend/telegram`: раздельные соединение, кэш, обновления, каталог, история, отправка, преобразование текста/медиа/обоев. Version guard исключает обновления старого соединения после переподключения.
- `backend/ai`: Spring AI, типизированный контекст, каталог, управление локальными моделями и образцы стиля; `model` — генерация и итоговый ответ, `research` — поиск и погода. Подробнее: [сервисы ИИ](../ai/ru.md).
- `backend/automation`: общая ограниченная очередь ответов, черновиков и памяти, объединение реплик, отмена устаревшей генерации, задержки и rate limits. Параллельность настраивается; доставка в одной беседе остаётся упорядоченной.

- `backend/monitoring`: OSHI-сэмплы CPU/RAM/процессов/сети и необязательные GPU-данные NVIDIA.
- `web/src/modules`: рабочая область, настройки, сообщения, память и мониторинг. Production-запросы вызывают generated-операции через workspace alias `@aigram/api-client`; общие компоненты, темы и переводы находятся в `shared`.

Пути выше относятся к `backend/src/main/kotlin/ru/aigram`, если не указан другой корень. Каждый Kotlin-класс находится в отдельном файле. Прежний HTTP-сервер, роутер и мост `SettingKey` удалены.

## Данные и границы

Данные хранятся в `%LOCALAPPDATA%/Aigram`; десктоп безопасно переносит существующий профиль из Tiho. Настройки записываются атомарно. Telegram credentials используют Windows DPAPI; TDLib-сессия не переносится между Windows-пользователями копированием ключей. Код и пароль входа не сохраняются. Известные ID автоответов сохраняются отдельно, используются для отметки ИИ и исключения из образцов личного стиля.

Запуск ставит очередь на паузу, если в настройках явно не включён `resumeOnStartup`. Вместе с Windows приложение открывается в трее. Группы по умолчанию выключены; настройка беседы переопределяет общую. Отправка учитывает выбранный режим reply/send и forum topic ID. При ручном ответе или смене настроек ожидающая генерация отменяется.

Промпты, словари языков, ошибки и модели находятся в `resources`. `ResourceCatalog` кеширует файлы и шаблоны; подстановка выполняется один раз, без повторного исполнения переменных из переписки. Языковые словари загружаются по `languages.json`; форматы идентификаторов проверяются типизированными правилами и стандартными парсерами. Конкретные исключения находятся в `exception/impl`, тексты — `errors/ru`.

Приложение показывает media. Контекст содержит текст и подписи; при включённом анализе изображений последнее фото или альбом передаётся непосредственно модели с поддержкой зрения. Распознавания речи нет. Нативная оболочка не предоставляет веб-коду Node API. Локальный servlet API проверяет cookie, Host и Origin. JSON ограничен 512 КиБ, включая chunked-запросы; сырые загрузки имеют отдельный лимит 100 МиБ. Для медиа сохранены byte ranges и ограниченная распаковка стикеров. Статический export загружается из упакованных ресурсов. Диагностический журнал не содержит переписки и секретов; полные трассировки ИИ сохраняются отдельно в истории событий.

Создание Spring-контекста запускает loopback servlet listener; авторизация Telegram, прогрев и фоновые сборы начинаются после явного `ApplicationRuntime.start()`. Runtime публикует `launch.url` только после получения блокировки профиля. При полном выходе закрываются инициативы, память, prefetch, очередь, servlet listener, собственная Ollama, мониторинг и Telegram. Закрытие ресурсов идемпотентно, включая очистку частично созданного контекста. Внешние серверы Ollama не завершаются.

## Сборка

Gradle проверяет и собирает единый OpenAPI перед тремя генераторами. Веб-сборка зависит от generated TypeScript SDK; самостоятельные npm-команды выполняют `sdk:check`, отдельной схемы и транспорта только из типов нет. Docker создаёт тот же SDK на JDK-этапе.

`web` создаёт static export, Gradle включает его в backend distribution. `scripts/build.ps1` создаёт иконку из SVG, Java runtime через jlink, затем Electron portable через electron-builder. Итог — один `complie/Aigram.exe`, а SDK для внешних потребителей упаковывается отдельно в `Aigram-API-Client.tgz`. Ollama/модели остаются отдельными загрузками. CI Windows выполняет проверки, сборку и браузерные сценарии, затем публикует релиз при push в main. Результаты текущей миграции фиксируются в [плане и проверках](../migration/ru.md).
