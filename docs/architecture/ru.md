# Архитектура

Electron владеет нативным окном, треем и автозапуском. Он запускает единственный Kotlin-процесс и ожидает `launch.url` в каталоге данных. Kotlin раздаёт статический Next.js export и локальный API. Адрес и секрет никогда не передаются внешним сервисам; после установки cookie секрет удаляется из истории окна.

## Модули

- `desktop/src`: lifecycle `Backend`, `TrayController`, `StartupRegistration`, main и изолированный preload. Нативное перемещение реализовано через `-webkit-app-region: drag`; maximize использует рабочую область Windows, fullscreen отключён.
- `backend/configuration`: Google Guice, явные singleton bindings, настройки окружения. `Main` получает `ApplicationRuntime` из контейнера.
- `backend/application`: блокировка профиля, запуск интеграций, координированное завершение. `engine` завершается перед Telegram, чтобы не оставлять локальный Ollama при долгом закрытии TDLib.
- `backend/http`: сессия, router, чтение/валидация/ответы, отдельные endpoint-классы по функциональности. `SettingKey` задаёт типы PATCH-настроек.
- `backend/telegram`: раздельные соединение, кэш, обновления, каталог, история, отправка, преобразование текста/медиа/обоев. Version guard исключает обновления старого соединения после переподключения.
- `backend/ai`: Spring AI, типизированный контекст, каталог, управление локальными моделями и образцы стиля; `model` — генерация и итоговый ответ, `research` — поиск и погода. Подробнее: [сервисы ИИ](../ai/ru.md).
- `backend/automation`: последовательная очередь, объединение реплик, отмена устаревшей генерации, задержки и rate limits.

- `backend/monitoring`: OSHI-сэмплы CPU/RAM/процессов/сети и необязательные GPU-данные NVIDIA.
- `web/src/modules`: рабочая область, настройки, сообщения, память и мониторинг. Общие компоненты и контракт находятся в `shared`.

Пути выше относятся к `backend/src/main/kotlin/ru/aigram`, если не указан другой корень. Каждый Kotlin-класс находится в отдельном файле.

## Данные и границы

Каталог `%LOCALAPPDATA%/Tiho` остаётся прежним. Настройки записываются атомарно. Telegram credentials используют Windows DPAPI; TDLib-сессия не переносится между Windows-пользователями копированием ключей. Код и пароль входа не сохраняются. Известные ID автоответов сохраняются отдельно, используются для отметки ИИ и исключения из образцов личного стиля.

Обычный запуск ставит очередь на паузу. `--startup` может возобновить её только при сохранённом `resumeOnStartup`. Группы по умолчанию выключены; настройка беседы переопределяет общую. Ответ сохраняет исходный message ID и forum topic ID. При ручном ответе или смене настроек ожидающая генерация отменяется.

Промпты, словари языков, ошибки и модели находятся в `resources`. `ResourceCatalog` кеширует файлы и шаблоны; подстановка выполняется один раз, без повторного исполнения переменных из переписки. Языковые словари загружаются по `languages.json`; форматы идентификаторов проверяются типизированными правилами и стандартными парсерами. Конкретные исключения находятся в `exception/impl`, тексты — `errors/ru`.

Приложение показывает media, но не распознаёт содержание изображений/речи. Модель получает текст и подписи вложений. Нативная оболочка не предоставляет веб-коду Node API. HTTP-мост проверяет cookie, Host и Origin, ограничивает размер тела запроса и доступ к media. В журнал работы не записывается содержимое переписки.

## Сборка

`web` генерирует TypeScript-типы OpenAPI и static export; Gradle включает его в backend distribution. `scripts/build.ps1` создаёт иконку из SVG, Java runtime через jlink, затем Electron portable через electron-builder. Итог — один `complie/Aigram.exe`; Ollama/модели остаются отдельными загрузками. CI Windows выполняет проверки, сборку и браузерные сценарии, затем публикует релиз при push в main.
