# Model connections and task routing

The workspace, catalog and model settings share one connection-list snapshot and in-flight read. Saving or deleting refreshes all open views; an older response cannot restore a removed connection. Reads pause in a hidden window and revalidate when it becomes visible or another view opens. Closing the final consumer cancels its display request and releases listeners. There is no background polling or time-based cache. These local list reads never test a provider or start model inference.

Aigram keeps the built-in local Ollama catalogue and also supports named model connections. In Settings → Models add an Ollama or OpenAI-compatible profile, enter its base URL and the exact model ID supplied by the provider, and choose it as the global or per-chat model. OpenAI, DeepSeek, OpenRouter, Groq and custom endpoints have editable presets. Presets do not promise that every model supports vision, reasoning or structured output.

Saving and listing profiles makes no provider requests. **Test connection** sends one short synthetic prompt only after an explicit confirmation; an API provider may charge for it. It sends no Telegram history or memory. API keys are write-only and stored separately using Windows DPAPI for the current OS user. GET responses and model traces contain no key. Empty key input preserves the current key; explicit Clear removes it. Changing the destination origin discards the previous credential. Credentials cannot be copied to another Windows user as plain configuration.

When a remote connection is used, the selected provider receives the conversation context and memory needed for that request. Photo analysis is separately enabled per chat and requires a profile whose Vision capability is enabled. Images are supplied as request data, not private local URLs. Never enable a capability the selected model does not support. Provider refusals are reported explicitly and are not bypassed with retries or fallback providers.

Options include output/context budgets, nullable sampling values, seed, stop sequences, reasoning options and connection/idle/total timeouts. Unset API sampling values are omitted. Native-only parameters are not sent as OpenAI API fields. For API profiles, a conservative UTF-8 text estimate trims old history to the context budget while retaining system instructions and the latest message. It does not reproduce the provider tokenizer or image-token accounting; the provider enforces actual limits. Total timeout zero allows active generation to continue; idle timeout still detects stalled streams. Reasoning tokens are part of the output budget for supported models. The provider remains the authority on supported values and context limits.

Optional task routing assigns reply, memory and vision to separate profiles. An explicit per-chat reply profile wins over global reply routing. Missing assignments use the main model (vision follows the chat reply target; memory follows the global model). Independent scheduling is opt-in: local Ollama connections share one inference resource, and different remote profiles can run independently. This does not make one GPU process multiple models faster. Automatic replies, manual drafts and memory collection share the configurable bounded task queue; delivery to each chat remains ordered. A profile referenced by settings, chat rules or routing cannot be deleted until those references are changed.

Public profiles and routing live in `models/profiles.json` and `models/routing.json` beneath the application data directory. Encrypted secrets live in `models/credentials/<profile-id>.credentials`. Local Ollama models continue to use their existing storage.

Contract: [api.yaml](../../backend/contract/api/schema/api.yaml), `/api/model-profiles` and `/api/model-routing`.

Implementation references: [Spring AI OpenAI](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html), [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Groq compatibility](https://console.groq.com/docs/openai), [DeepSeek](https://api-docs.deepseek.com/), [OpenRouter](https://openrouter.ai/developers).

Credentials are encrypted together with their destination origin. A failed metadata write cannot make a newly entered key available to a previous host. An unbound or mismatched credential fails closed and must be entered again; it is never sent speculatively.
