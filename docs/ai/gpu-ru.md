# Устройство вычислений Ollama

В настройках доступны **Автоматически**, **CPU** и отдельные совместимые **видеокарты NVIDIA**. Параметр относится к серверу Ollama, который запускает приложение, и ко всем моделям этого сервера. Разные модели не закрепляются за разными видеокартами.

Список NVIDIA собирается через `nvidia-smi.exe`: UUID карты, название, память, вычислительная архитектура и версия драйвера. Перед PATH проверяется стандартное расположение в Windows System32. Порядковые номера OSHI, Windows и Vulkan не используются как идентификаторы CUDA. Архитектуру ниже compute capability 5 нельзя выбрать явно для CUDA. Старый драйвер вызывает рекомендацию обновления, не запрет выбора: фактическую совместимость проверяет установленная Ollama. Текущая официальная рекомендация — драйвер 550+, а для compute capability 5.0–6.2 — 570+. Обнаружение кешируется на 30 секунд; команда ограничена двумя секундами. Если карту определить не удалось, у локально управляемого движка остаются автоматический режим и CPU.

Проверки опираются на [официальные требования Ollama и описание выбора GPU](https://docs.ollama.com/gpu). Совместимый идентификатор не гарантирует, что конкретная модель помещается в видеопамять: Ollama может использовать CPU полностью или частично. Активный режим показывает параметр запуска процесса, а не измеренную загрузку видеокарты.

## Применение настройки

Сохранение `ollamaDevice` не перезапускает Ollama, не устанавливает драйверы и не скачивает модели. Параметр передаётся следующему дочернему процессу Ollama, запускаемому приложением. Для уже работающего управляемого сервера показано ожидающее изменение. После полного перезапуска приложения управляемая Ollama запускается с новым параметром.

- **Автоматически** сохраняет окружение родительского процесса, включая пользовательские маски CUDA, HIP и Vulkan. Существующие внешние настройки не сбрасываются.
- **CPU** скрывает от дочернего процесса устройства CUDA, HIP/ROCm и Vulkan и отключает Vulkan-бэкенд.
- **UUID NVIDIA** оставляет видимой выбранную карту CUDA и скрывает альтернативные устройства HIP/ROCm и Vulkan, чтобы Ollama не выбрала другую видеокарту через иной бэкенд.

Переменные меняются только для нового дочернего процесса. Пользовательские и системные переменные Windows не редактируются. Если сохранённый UUID временно пропал, настройка сохраняется: другая карта не выбирается автоматически. Новый UUID, отсутствующий среди обнаруженных совместимых карт, выбрать нельзя.

## Внешние службы и AMD/Intel

Приложение не может изменить выбор GPU в уже работающем внешнем процессе Ollama, службе Windows, Docker или на удалённом сервере. API и интерфейс прямо показывают это ограничение. Такие службы продолжают работать; параметры задаются в месте их запуска. См. [настройку окружения Ollama в Windows](https://docs.ollama.com/faq#setting-environment-variables-on-windows).

AMD и Intel остаются под автоматическим управлением Ollama. Для явного выбора AMD нужен проверенный идентификатор HIP/ROCm, для Vulkan — настоящий индекс устройства этого бэкенда. OSHI их не предоставляет. Эта версия не выдумывает соответствие и не устанавливает ROCm/Vulkan. Документация AMD отдельно описывает [переменные изоляции Windows HIP и Linux ROCr](https://rocm.docs.amd.com/projects/HIP/en/latest/reference/env_variables.html#gpu-isolation-variables).

## Локальный API

[OpenAPI](../../backend/contract/api.yaml) описывает `GET /api/engine/devices` и `PATCH /api/settings` с `ollamaDevice: auto | cpu | GPU-UUID`. Обнаружение устройств требует локальную сессию. Ответ содержит выбранный и известный активный режимы, признак управляемого процесса, доступность выбора, необходимость перезапуска и ограничения. Неподдерживаемое новое значение возвращает `INVALID_OLLAMA_DEVICE` с HTTP 400.
