# Подключения моделей и распределение задач

Aigram сохраняет каталог локальных моделей Ollama и поддерживает именованные подключения. В настройках моделей создайте профиль Ollama или OpenAI-compatible, укажите адрес и точный ID модели у провайдера, затем выберите его для приложения или отдельного чата. Есть редактируемые шаблоны OpenAI, DeepSeek, OpenRouter, Groq и произвольного сервера. Шаблон не означает, что любая модель провайдера поддерживает изображения, рассуждения и JSON Schema.

Сохранение и просмотр профилей не обращаются к провайдеру. Кнопка проверки отправляет один короткий искусственный запрос после явного подтверждения; API может быть платным. Переписка Telegram и память в проверку не передаются. Ключи доступны только для записи и хранятся отдельно, зашифрованными Windows DPAPI для текущего пользователя ОС. API-ответы, диагностика и журнал запросов не содержат ключей. Пустое поле сохраняет предыдущий ключ, явная очистка удаляет его. При смене origin адреса прежний ключ удаляется. Нельзя переносить зашифрованные ключи другому пользователю Windows как обычный конфиг.

При использовании удалённой модели провайдер получает контекст и память, необходимые для запроса. Анализ фотографий отдельно включается для чата и требует включённой возможности Vision. Изображения передаются данными запроса, а не недоступными провайдеру локальными ссылками. Возможности модели нужно указывать по её документации. Отказ провайдера показывается как явная причина и не обходится повторными запросами или сменой провайдера.

Настраиваются лимиты ответа и контекста, sampling, seed, stop, рассуждения и таймауты соединения, простоя и всего запроса. Незаданные sampling-поля не отправляются в API. Параметры только для Ollama не подмешиваются в OpenAI-запрос. Для API консервативная оценка текста по UTF-8 отбрасывает старую историю в пределах бюджета, сохраняя системные инструкции и последнее сообщение. Это не копия токенизатора провайдера и не точный расчёт стоимости изображений; фактические лимиты проверяет провайдер. Общий таймаут 0 разрешает долгую активную генерацию; таймаут простоя продолжает обнаруживать зависший поток. Для моделей с reasoning токены рассуждений входят в бюджет ответа. Допустимые значения и пределы определяет провайдер.

Включаемое распределение назначает профили для ответа, памяти, планирования поиска и изображений. Явный выбор модели чата имеет приоритет над глобальным маршрутом ответов. Пустое назначение использует основную модель: поиск и изображения следуют модели ответа чата, память — глобальной. Независимое выполнение включается отдельно: все локальные Ollama используют общий ресурс генерации, разные удалённые профили могут работать независимо. Это не обещает ускорение нескольких моделей на одной видеокарте. Автоответы чатов обрабатываются последовательно. Используемый в настройках, чатах или маршрутах профиль сначала нужно заменить, затем удалить.

Публичные профили и маршруты находятся в `models/profiles.json` и `models/routing.json` внутри каталога данных приложения. Зашифрованные ключи — в `models/credentials/<profile-id>.credentials`. Хранилище локальных моделей Ollama сохраняется.

Контракт: [api.yaml](../../backend/contract/api.yaml), `/api/model-profiles` и `/api/model-routing`.

Источники реализации: [Spring AI OpenAI](https://docs.spring.io/spring-ai/reference/api/chat/openai-chat.html), [OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create), [Groq](https://console.groq.com/docs/openai), [DeepSeek](https://api-docs.deepseek.com/), [OpenRouter](https://openrouter.ai/developers).

Ключ шифруется вместе с origin назначения. Ошибка сохранения метаданных не позволяет отправить новый ключ на прежний сервер. Ключ без привязки или с несовпадающим адресом не отправляется; его нужно ввести заново.
