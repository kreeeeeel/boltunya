# Модели по задачам и локальный анализ изображений

В **Настройки → Распределение задач** для каждой задачи можно выбрать установленную модель Ollama или сохранённое подключение API:

| Задача | Назначение |
| --- | --- |
| Ответы | Генерация ответа с выбранным стилем общения и контекстом. |
| Память | Суммаризация подходящих диалогов и фактов. |
| Поиск | Подготовка поиска актуальной информации. Итоговый текст по-прежнему пишет модель ответов. |
| Анализ изображений | Генерация итогового ответа с изображением, историей, памятью и выбранным стилем за один запрос к модели. |

Включите распределение, выберите модели и сохраните. При выборе Ollama сохраняется непосредственно тег модели; дополнительный профиль подключения не создаётся. Подключение API и локальный тег для одной задачи взаимоисключающие. Сохранение распределения не запускает генерацию или скачивание.

Явно выбранная модель ответов в параметрах диалога имеет приоритет над общим назначением ответов. Собственное назначение задачи имеет приоритет над наследованием. Без назначения память использует общую модель по умолчанию, а поиск и анализ изображений наследуют фактическую модель ответов. Наследуемая модель для изображений должна поддерживать зрение. При выключении распределения сохраняется обычный выбор общей модели и модели диалога. Назначения сохраняются после перезапуска.

Модели, установленные вне встроенного каталога, тоже появляются в списке. Их неподтверждённые размер, ёмкость контекста, требования к памяти, скорость и качество показываются как неизвестные. Поддержка изображений у таких моделей не предполагается. Для собственной визуальной модели можно создать профиль Ollama и явно включить проверенную поддержку изображений.

## Изображения через Ollama

Включите **Анализировать фото** в параметрах диалога и выберите установленную визуальную модель для задачи анализа изображений. Aigram передаёт байты изображения как Spring AI `Media` в сообщении пользователя; библиотека использует нативное поле Ollama `images`. Локальная ссылка на файл модели не отправляется. Выбранная визуальная модель сразу формирует итоговый ответ, второй запрос к текстовой модели не требуется.

В каталоге зрение отмечено у Gemma 3 4B/12B/27B, представленных вариантов Qwen 3.5 и Qwen3-VL 2B/4B/8B. Gemma 3 1B работает только с текстом. Под поиском моделей находятся категории **Все**, **Генерация** (модели, ориентированные на текст) и **Анализ изображений**. Мультимодальные модели также подходят для текстовых ответов.

У добавленных тегов Qwen3-VL ёмкость контекста модели — 256K, размер скачивания — примерно 1,9 ГБ, 3,3 ГБ и 6,2 ГБ соответственно. Настроенный контекст генерации может быть меньше предельной ёмкости модели. Требования к памяти в каталоге ориентировочные, а время ответа измеряется только при явном запуске проверки скорости.

Используется существующий адаптер Ollama из Spring AI. Несовместимая модель для изображений отклоняется до скачивания фото из Telegram для генерации. Подключения API продолжают использовать заявленные возможности; удалённый анализ учитывает явную настройку анализа фото в диалоге.

## Параллельность

Распределение определяет модель, а общая очередь — число одновременных задач. Локальные задачи используют существующую общую группу ресурсов генерации. Выбор разных локальных моделей не обещает параллельную работу на одной видеокарте и не обходит очередь самой Ollama.

Официальные источники: [мультимодальность Spring AI Ollama](https://docs.spring.io/spring-ai/reference/api/chat/ollama-chat.html), [варианты Gemma 3](https://ollama.com/library/gemma3), [Qwen 3.5](https://ollama.com/library/qwen3.5), [Qwen3-VL 2B](https://ollama.com/library/qwen3-vl:2b), [4B](https://ollama.com/library/qwen3-vl:4b) и [8B](https://ollama.com/library/qwen3-vl:8b).
