# Голосовые сообщения

Aigram может локально распознавать входящие голосовые Telegram и озвучивать ответы. Для речи используются sherpa-onnx, Whisper tiny и скачиваемые голоса Piper. Сам ответ по-прежнему пишет выбранная модель диалога. Ключ речевого API и отдельная голосовая модель Ollama не нужны.

## Настройка

Откройте **Настройки → Помощник → Голос**. Скачайте **Sherpa runtime**, **Whisper tiny** для распознавания и голос для озвучивания. Каждое скачивание запускается явно, показывает прогресс и поддерживает отмену. Перед установкой проверяется закреплённая SHA-256. Скачивание голоса не включает автоответы.

Доступны русские Ирина и Руслан и английская Amy. У голосов разные лицензии, включая некоммерческие и неуточнённые условия исходных данных; они указаны в карточках. Дополнительный runtime содержит eSpeak NG. [Источники, лицензии и устройство runtime](runtime-ru.md).

Распознавание входящих включается отдельно. Режимы ответа:

- **Текст:** автоматические ответы остаются текстовыми.
- **Всегда голосом:** ответы модели озвучиваются.
- **Случайно:** для каждого ответа независимо применяется выбранная вероятность.
- **Голосом на голос:** голосовой ответ только на голосовое сообщение. Музыкальные файлы не считаются голосовыми.

Выберите модель распознавания, голос и скорость речи. Настройки речи общие; разрешения беседы, задержки, ответ на сообщение и ограничения групп продолжают действовать. Точный заранее заданный текст для поддержки диалога отправляется текстом. По умолчанию речь отключена. Если моделей нет, приложение сообщает об этом и не скачивает их само.

## Что происходит

Подходящее голосовое загружается через TDLib, преобразуется в моно PCM 16 кГц и распознаётся. Только в контексте модели вместо заглушки появляется расшифровка. Авторы, время, выбранный стиль, память и исключения из контекста сохраняются. Само сообщение Telegram не изменяется. Удалённые и исключённые сообщения для генерации не распознаются.

Модель диалога пишет текст для произнесения. Piper озвучивает его, кодек формирует OGG/Opus с длительностью и волной. TDLib отправляет настоящее голосовое с учётом ответа на сообщение и темы беседы. Автоматическая отправка сохраняет признак ИИ.

Распознавание и озвучивание работают в общей очереди. События показывают этапы **Распознаём голос** и **Озвучиваем ответ**. Речевой движок дополнительно ограничен одним отдельным процессом, двумя потоками CPU и JVM heap 512 МБ; память нативных моделей расходуется дополнительно. Отмена прерывает задачу и завершает её речевой процесс, не затрагивая чужой Ollama.

Первая версия распознаёт последнее подходящее входящее голосовое и повторно использует расшифровки, полученные в текущей сессии. Массовой расшифровки старых голосовых и передачи их в постоянный сборщик памяти пока нет. Ограничения: вход до 25 МиБ и десяти минут; текст озвучивания до 4096 символов, результат до десяти минут. Длинные записи могут обрабатываться заметное время.

## Проверка перед отправкой

В диалоге откройте **Подготовить ответ с ИИ** и выберите текст или голос. Голосовой черновик содержит плеер и редактируемый текст. Изменение текста сразу делает старую запись недействительной. **Обновить голос** ставит в очередь озвучивание именно исправленного текста без повторного переписывания моделью. До готовности новой записи отправка недоступна. Обычный черновик в поле сообщения сохраняется.

Аудио доступно только через защищённый локальный API для текущего аккаунта и конкретной беседы. Записи временные; файл неопределённо завершившейся нативной отправки сохраняется, поскольку TDLib ещё может загружать его. Текст не попадает в аргументы запуска процесса и публичный журнал ошибок.

## Проверка и импорт в настройках

Настоящий локальный синтез в изолированном профиле:

![Настоящая проверка локального голоса в настройках Aigram](../resources/voice-settings-local.png)

В блоке **Проверка голоса** вводите текст и слушайте настоящую локальную озвучку. Используются выбранные сейчас голос и темп, даже если настройки ещё не сохранены. Проверка работает в общей очереди, показывает состояние и поддерживает отмену. Чат-модель не вызывается, сообщения в Telegram не отправляются. Записи проверки нельзя отправить через API черновиков. Проверка доступна и до входа в Telegram.

Над каталогом находятся одинаковые по стилю кнопки **Обновить список**, **Проводник** и **Импортировать**. Обновление перечитывает установленные ресурсы. В десктопном приложении Проводник открывает только фиксированную папку `speech` текущего профиля, когда она уже существует; произвольный переданный путь открыть нельзя.

Для импорта нужен совместимый **пакет sherpa-onnx VITS/Piper `.tar.bz2`**: до 100 МиБ в архиве и 512 МиБ после распаковки. Внутри должна быть одна верхняя папка с одной ONNX-моделью, `tokens.txt` и полной `espeak-ng-data`, включая `phondata`, `phonindex` и `phontab`. Исходные лицензии и карточка модели сохраняются. Перед импортом войдите в Telegram, затем укажите понятное название, при необходимости язык и условия использования. Импортированный голос появляется в обычном выборе озвучивания и сохраняется после перезапуска. Официальный runtime скачивается отдельно с проверкой хеша. Импорт проверяет структуру пакета; введённое название лицензии само по себе не подтверждает происхождение модели и права на её использование.

Обычная запись WAV, Python checkpoint или произвольная ONNX-модель не являются готовым голосом этого формата. Найденный голос «Алисы» можно использовать, если это совместимый пакет; загрузка записи сама по себе не клонирует голос. Повреждённый пакет выдаёт ошибку и не заменяет установленные модели. Если файлы своего голоса потеряны, приложение сообщает об этом и не пытается скачать его с выдуманного адреса.

## Хранение и настоящие проверки

Речевые файлы находятся в `speech/` активного профиля Aigram. По умолчанию это `%LOCALAPPDATA%/Aigram`; отдельный профиль задаётся через `AIGRAM_DATA_DIR`. Модели хранятся в `speech/<asset-id>`, черновики в `speech/generated`, рабочие файлы в `speech/work`. Каталог моделей Ollama отдельный. Расшифровки сохраняются только в оперативной памяти.

Для настоящих изолированных проверок положите закреплённые файлы в `build/speech-verification` и задайте `AIGRAM_LIVE_SPEECH=true`. `LiveSpeechPipelineTest` проверяет установку, синтез, Opus и сохранение произнесённых слов в расшифровке Whisper; пунктуация может отличаться. `LiveSpeechVoicesTest` проверяет голоса каталога. `LiveSpeechSettingsTest` загружает настоящий архив Piper через локальный HTTP API, импортирует и озвучивает введённый текст без чат-модели и отправки в Telegram.

Последняя проверка загрузки, импорта и получения аудио через настройки прошла за 15,782 секунды с настоящим пакетом Piper размером 21 МБ. Настоящий цикл TTS → Opus → Whisper прошёл за 36,130 секунды, а установка и синтез Ирины, Руслана и Amy — за 34,490 секунды. Это полное время тестов на проверочной машине, а не обещание скорости. Прежняя непостоянная ошибка установки Руслана в финальном прогоне всех голосов не повторилась; причина не установлена, добавлена тестовая диагностика.

Финальный backend quality gate прошёл: 619 Kotlin-сценариев, ноль ошибок и 14 пропусков. Проверки SDK, UI, Electron и скриптов также прошли. Полный браузерный прогон проверил 135 сценариев, после последних правок прошли все восемь голосовых сценариев. Настоящая распакованная Aigram 2.6.39 прошла синтез через API, настройки и прослушивание за 44,259 секунды со встроенными JVM и кодеком в новом профиле без авторизации. Публикация Windows-релиза, проверка скачанного EXE и перезапуск настоящего профиля ещё обязательны. [Подробные результаты и отдельная проверка EXE](runtime-ru.md#проверка).
