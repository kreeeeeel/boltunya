# Локальный речевой движок

Aigram поддерживает два отдельных локальных CPU-движка для Windows x64. Официальный **Java API sherpa-onnx 1.13.8** выполняет распознавание Whisper и синтез Piper/VITS. **Applio 3.7.0** преобразует готовую запись в тембр выбранной RVC-модели. RVC — конверсия голоса, а не самостоятельное чтение текста: цепочка выглядит как **Piper → WAV → Applio/RVC → WAV → Ogg/Opus**. При ошибке конверсии возвращается ошибка, а не подмена голосом базового Piper.

Для новых загрузок доступны **32 русских/английских голоса: 17 Sherpa/Piper и 15 RVC-моделей**, а также два движка и Whisper tiny. Уже установленные голоса на других языках и импортированные модели сохраняют ID и остаются доступными для выбора. Неустановленные иностранные голоса не предлагаются для новых загрузок. Таблица содержит примеры зависимостей и голосов, а не все 32 модели; точные источники и условия приведены в [полном каталоге](catalog-ru.md).

| ID ресурса | Размер загрузки, байт | Назначение |
| --- | ---: | --- |
| `sherpa-runtime` | 8 277 046 | JNI-движок для Windows x64 CPU |
| `applio-runtime` | 6 775 972 339 | Portable Python/PyTorch Applio 3.7.0; архив 6,31 ГиБ |
| `whisper-tiny` | 116 204 861 | Многоязычный Whisper tiny; используются int8 encoder/decoder |
| `piper-ru-irina` | 21 149 417 | Русский голос Ирина |
| `piper-ru-ruslan` | 21 127 907 | Русский голос Руслан |
| `piper-en-amy` | 21 099 246 | Английский голос Amy |
| `rvc-alice` | 64 237 755 | Community-модель YandexAliceRVC и FAISS-индекс; нужны Applio и русская Ирина |

В таблице указан объём загрузки, а не распакованных файлов. Запуск приложения, выбор голоса и запрос обработки не устанавливают недостающие ресурсы. Явная кнопка **Установить** ставит зависимости в очередь перед выбранной моделью; их размер виден до скачивания. Для распознавания по-прежнему доступны автоматическое определение, русский, английский, украинский и казахский; ограничение RU/EN относится к новым голосам синтеза. Маленький Whisper может ошибаться. Аудио не отправляется внешнему речевому сервису.

## Установка и проверка

Версионируемый [каталог](../../backend/src/main/resources/speech/catalog.json) содержит точные URL, размеры, SHA-256 и обязательные файлы. Sherpa использует небольшой официальный native JAR. Applio — закреплённый portable ZIP разработчиков; RVC-модели и индексы берутся из конкретных ревизий community-репозиториев. Разрешён только HTTPS и явный список GitHub/Hugging Face hosts, включая разрешённые перенаправления. До распаковки должны совпасть размер и SHA-256.

Архив распаковывается в отдельную временную папку; завершённая установка публикуется атомарным перемещением. Ошибка или отмена не создаёт установленный ресурс. Ограничения:

| Архив | Максимум элементов | Максимальный распакованный объём |
| --- | ---: | ---: |
| Каталожный Sherpa/Piper `.tar.bz2` | 4096 | 512 МиБ |
| Каталожная RVC-модель ZIP | 4096 | 512 МиБ |
| Каталожный движок Applio ZIP64 | 50 000 | 12 ГиБ |

Отклоняются выход за пределы папки, абсолютные пути, ссылки, дубликаты и опасные Windows-имена в ZIP. Для ZIP дополнительно проверяются заявленный размер файлов и CRC. Сохраняются обязательные файлы и исходные уведомления. В проверенном архиве Applio 37 231 элемент общим распакованным объёмом 10 386 551 490 байт; перед загрузкой проверяется свободное место на архив плюс запас распаковки 12 ГиБ. Из portable-пакета берутся интерпретатор, исходники RVC, служебные модели и уведомления зависимостей; собственного pip-окружения Aigram не собирает.

Работает один поток установщика с ограниченной очередью и дедупликацией запросов. Установка RVC-голоса ставит Sherpa, Applio и базовый Piper перед его весами. Ошибка зависимости завершает родительскую установку ошибкой, а не оставляет её в очереди. Отмена голоса отменяет только те задания зависимостей, которые не нужны другому запросу. Отмена активного движка отменяет и зависимые планы установки, в том числе когда сам движок запрашивался отдельно. Уже установленная импортированная модель остаётся операцией без скачивания; отсутствующий Sherpa устанавливается явно.

Ресурсы хранятся внутри каталога данных приложения, обычно `%LOCALAPPDATA%/Aigram/speech/<asset-id>`. Маркер установки соответствует закреплённому артефакту. Незавершённые загрузки после перезапуска сами не возобновляются.

## Проверка в настройках и свои голоса

Встроенная проверка настроек ставит в очередь настоящий синтез переданного текста с выбранными голосом и темпом, без сохранения этих предпочтений и вызова чат-модели. Результат — временное Ogg/Opus-аудио через защищённый локальный API, с прослушиванием и отменой. Такую запись нельзя отправить через API голосовых черновиков. Проверка работает без входа в Telegram; для импорта модели нужен текущий авторизованный аккаунт.

Импорт загружает `.tar.bz2` через защищённый локальный API и проверяет архив в отдельной временной папке. Ограничения: 100 МиБ в архиве, 512 МиБ после распаковки и 4096 элементов. Пакет должен содержать одну верхнюю папку, одну ONNX-модель в её корне, `tokens.txt` и обязательные данные eSpeak. Выход за пределы папки, повторяющиеся пути, ссылки, специальные и исполняемые файлы отклоняются. Исходные уведомления модели и уведомления runtime Aigram сохраняются. Для импорта вычисляется локальная SHA-256; в отличие от каталога, закреплённого исходного артефакта у своей модели нет.

Успешный импорт атомарно публикует голос `custom-…` и запись в постоянном локальном реестре. После перезапуска он остаётся в обычном списке озвучивания. Этот путь поддерживает совместимые с Sherpa ONNX-пакеты, а не произвольные RVC/PTH/ZIP или исполняемые движки. Отсутствующие файлы обозначаются как незавершённая локальная установка; автоматического адреса скачивания у своей модели нет. **Обновить список** перечитывает состояние установок, а десктопная кнопка **Проводник** принимает только фиксированный идентификатор папки `speech`. [Поддерживаемый формат пакета](ru.md#проверка-и-импорт-в-настройках).

Ручное окно **Голосовое сообщение** создаёт отдельный черновик, привязанный к беседе. Установленный голос и скорость передаются только для этого запроса, без изменения общих настроек. **Проверить** необязательно: **Озвучить и отправить** ставит синтез в очередь и отправляет результат либо использует готовую неизменённую запись. Закрытие и отмена снимают намерение отправки до её начала. Неопределённую отправку нельзя повторить для той же записи, а после подтверждённой отправки ошибка обновления повторяет только чтение диалога. [Ручная озвучка и черновики ИИ](ru.md#проверка-перед-отправкой).

## Изоляция и приватность

Каждый этап Sherpa запускает собственный JVM-процесс без Spring. Текст передаётся ограниченным UTF-8 JSON через стандартный ввод; ответ — через ограниченный приватный файл, удаляемый после обработки. RVC запускает только установленный `env/python.exe -s -B -` с фиксированным UTF-8 bootstrap проверки устройства через стандартный ввод, который вызывает локальный `core.py infer`, и локальными путями WAV, модели и индекса. В обеих командных строках нет произносимого или распознанного текста. Нативные стандартные вывод и ошибки в production отбрасываются.

Нативные этапы используют общий последовательный слот и таймаут процесса десять минут. Sherpa использует два CPU-потока и Java heap 512 МиБ; нативная память выделяется дополнительно. Для Applio CPU-потоки по-прежнему ограничены двумя. Сохранённый `voiceConversionDevice` выбирает CPU (совместимое значение по умолчанию) или NVIDIA CUDA только для RVC-конверсии. В CPU-режиме CUDA скрыта от дочернего процесса; явный выбор CUDA проверяет установленный PyTorch и устройство Applio, завершаясь ошибкой вместо незаметного перехода на CPU. Java heap не ограничивает Python/PyTorch и видеопамять. Отмена завершает собственный процесс и потомков, а не внешний Ollama или чужие процессы. После каждой конверсии собственный процесс заканчивается. Промежуточный WAV Piper удаляется после конверсии, итоговый WAV — интеграцией после преобразования в Opus.

`GET /api/speech/compute` проверяет установленный движок по запросу, без весов моделей и озвучки. Проверка отделена от Ollama; фонового опроса оборудования и запуска при старте нет. Недоступная CUDA, отсутствующий движок и ошибка проверки различаются. Закреплённая [конфигурация Applio](https://github.com/IAHispano/Applio/blob/3.7.0/rvc/configs/config.py) обычно сама выбирает устройство, а [CLI инференса](https://github.com/IAHispano/Applio/blob/3.7.0/core.py) не имеет переключателя устройства. Фиксированный bootstrap проверяет запрошенное устройство без изменения установленных файлов. Доступность определяется [проверкой CUDA в PyTorch](https://docs.pytorch.org/docs/2.11/generated/torch.cuda.is_available.html); она не гарантирует достаточную VRAM или успешную генерацию.

Установщик, обновлятор, веб-сервер и облачный TTS Applio не запускаются. До старта проверяются реальные пути интерпретатора, CLI, модели, индекса, ContentVec и RMVPE. Python home/search paths указывают на установленный движок, пользовательские site packages отключены, Hugging Face и Transformers работают в offline-режиме. `APPLIO_CONFIG_FILE`, `APPLIO_CONFIG_DIR`, `APPLIO_ROOT`, `APPLIO_CODE_ROOT`, `APPLIO_LOGS_DIR`, `HF_HOME`, `TORCH_HOME`, `TEMP` и `TMP` явно ограничены движком или временной папкой запроса, заменяя унаследованные пути к посторонним профилям Applio.

Входной WAV остаётся во владении вызывающего кода, синтез возвращает WAV ему же. Временные файлы запросов, настроек и ответов очищаются при успехе и ошибке. Аудио и нативная диагностика не записываются в журнал ошибок приложения. Расшифровки в запросах к модели и текст проверки при авторизованном аккаунте могут сохраняться в приватной истории событий согласно её настройкам хранения и очистки.

Синтез принимает до 4096 единиц UTF-16 и скорость 0,5–2,0; для RVC скорость применяется к базовому Piper. Входное аудио ограничено 25 МиБ. Результат ограничен 600 секундами и 64 МиБ; конвертированный WAV должен быть signed 16-bit mono PCM с частотой 8–48 кГц. Кодек преобразует входящие Telegram voice в моно PCM WAV 16 кГц, а синтезированный WAV — в Ogg/Opus.

## Проверка

### Настоящая проверка RVC

Зафиксирован успешный локальный прогон синтетических проверок: `ApplioSpeechWorkerTest` — 3 сценария, `SpeechZipInstallerTest` — 4, `SpeechDependencyInstallTest` — 6 и `SpeechConversionTest` — 2. Эти 15 сценариев проверяют CPU/offline-запуск без текста в аргументах, изоляцию окружения, лимиты/обход пути/ссылки/Windows-алиасы в архивах, порядок/ошибки/отмену зависимостей, сохранение старых установленных голосов и очистку конверсии без подмены базовым голосом. Используются синтетические файлы и заглушки исполнителя; качество настоящего RVC-аудио этим не подтверждается. Это результаты отдельных проверок, а не заявление об успешном завершении всех проверок нынешнего релиза.

Настоящая проверка Алисы с закреплёнными Applio и community-моделью прошла: Piper → RVC → Opus → Whisper сохранил смысл произнесённого, а преобразованная запись отличается от базового голоса. Установка в отдельный профиль заняла 420,305 с; синтез записи длительностью 3,260 с — 82,607 с на двух потоках CPU; вся проверка — 508,497 с. Это измерения, а не обещание скорости. Сообщения в Telegram и запросы к чат-модели не отправлялись. Доказательство: `build/speech-verification/rvc-proof-1434426430849561619/proof.json`. Для остальных 14 RVC-голосов проверены метаданные, но не настоящее аудио.

Ожидаемая добровольная проверка использует только эти локальные архивы и уже сохранённые Sherpa, Ирину и Whisper tiny:

```powershell
$env:AIGRAM_LIVE_RVC = 'true'
.\gradlew.bat :backend:test --tests 'ru.aigram.speech.LiveRvcSpeechTest' --rerun-tasks
```

`LiveRvcSpeechTest` устанавливает ресурсы в новую `build/speech-verification/rvc-proof-*/profile`, выполняет настоящий Piper → Applio → Opus → WAV 16 кГц → Whisper и требует отличающийся WAV и узнаваемые синтетические слова. Telegram, настоящий профиль и генерация чат-модели не используются. Синтетическое аудио и отчёт с временем/логическими результатами сохраняются в этой папке; расшифровка в отчёт не добавляется. До успешного результата нельзя заявлять о проверенной работе RVC. Проверка упакованного приложения ниже по-прежнему подтверждает Sherpa, а не Applio.

### Историческая исходная проверка Sherpa

Unit- и HTTP-регрессии исходного речевого релиза проверяют размер и контрольную сумму, защиту распаковки от обхода пути и ссылок, состояние установки, отмену, запуск без сети, выбор моделей, точный Unicode-текст для синтеза, очистку файлов протокола, разделение проверки и отправки и сохранение импортированной модели. Его финальный Gradle gate завершён: 619 Kotlin-сценариев, ноль ошибок и 14 пропусков — 12 несвязанных добровольных проверок ИИ/сети/памяти и две проверки прав на символьные ссылки Windows. Прошли 12 тестов установленного SDK, полный набор из 257 UI-тестов, 39 Electron-тестов и 10 тестов скриптов. Дополнительный точечный прогон проверил 16 тестов в четырёх файлах, включая три новые регрессии хука. Это исторические результаты исходной версии. Новые локальные результаты расширенного каталога записаны в основном руководстве речи; публикация проверяется отдельно.

Настоящие тесты включаются явно через `AIGRAM_LIVE_SPEECH=true` и используют ранее скачанные артефакты из `build/speech-verification`. Прошли следующие изолированные проверки:

| Проверка | Настоящая обработка | Время |
| --- | --- | ---: |
| `LiveSpeechSettingsTest` | Загрузка настоящего архива Piper размером 21 МБ через HTTP, импорт, озвучивание введённого текста и получение Ogg-аудио для прослушивания | 15,782 с |
| `LiveSpeechPipelineTest` | Проверяемая установка → русский синтез Piper → Ogg/Opus → моно WAV 16 кГц → распознавание Whisper | 36,130 с |
| `LiveSpeechVoicesTest` | Установка и синтез трёх исходных голосов каталога: Ирина, Руслан и Amy | 34,490 с |

В прогоне трёх исходных голосов установка заняла 14 866 мс, синтез Ирины — 3886 мс, Руслана — 3673 мс, Amy — 5994 мс. Прежняя непостоянная ошибка установки Руслана не повторилась в отдельной и финальной проверках трёх голосов; её причина не установлена. Тестовая диагностика фиксирует ошибки установки без изменения production-поведения.

Цикл сохранил произнесённые слова; пунктуацию Whisper восстанавливает сам, поэтому её точное совпадение не требуется. Общее время тестов включает подготовку и очистку, а не только работу модели, и зависит от проверочной машины. Проверки не обращаются к Telegram, не используют настоящий профиль приложения и не меняют модели Ollama. Полный браузерный прогон исходного релиза проверил 135 сценариев; после его правок сворачиваемого заголовка и хука прошли все восемь голосовых сценариев (`build/speech-browser-last.log`). Эти числа не относятся к новому каталогу и ручному окну. Браузерные фикстуры отдельно проверяют управление; проверка EXE ниже также использует настоящий синтез и прослушивание.

## Отдельная проверка упакованного приложения

Эта явно запускаемая Windows-проверка использует настоящие встроенные JVM, речевой процесс и кодек. Она не входит в обычный набор тестов и ничего не скачивает. Сначала установите npm-зависимости проекта и положите закреплённые каталогом `sherpa-onnx-native-lib-win-x64-1.13.8.jar` и `vits-piper-ru_RU-irina-medium-int8.tar.bz2` в `build/speech-verification`. Из корня репозитория выберите распакованную сборку или скачанный portable EXE:

```powershell
$env:AIGRAM_TEST_EXECUTABLE = (Resolve-Path '.\complie\win-unpacked\Aigram.exe').Path
npm --prefix desktop run test:speech

# Для проверки скачанного релиза:
$env:AIGRAM_TEST_EXECUTABLE = 'C:\Downloads\Aigram.exe'
npm --prefix desktop run test:speech
```

Старое имя `BOLTUNYA_TEST_EXECUTABLE` также поддерживается; без обоих переопределений используется `complie/win-unpacked/Aigram.exe`. Скрипт проверяет размеры и SHA-256 исходных файлов, создаёт новый `build/speech-verification/packaged-profile-*` и запускает приложение без Telegram-аккаунта и проверки обновлений. Он вызывает настоящий API проверки, запускает озвучивание и прослушивание в настройках, проверяет отсутствие запросов генерации через локальный перехватчик Ollama, закрывает своё приложение и проверяет удаление `launch.url`.

Для portable EXE скрипт использует установленный Windows 7-Zip: извлекает только фиксированный NSIS payload `$PLUGINSDIR/app-64.7z`, затем распаковывает приложение в новый `build/speech-verification/packaged-extract-*`. Проверяет наличие `Aigram.exe` и `resources/app.asar` и запускает извлечённое приложение; отладчик не подключается к оболочке NSIS. Уже распакованный EXE с соседним `resources/app.asar` запускается напрямую. В отчёт попадают SHA-256 исходного EXE и запускаемого EXE payload, а `portablePayloadExtracted` указывает выбранный путь. Папка распаковки сохраняется вместе с остальными синтетическими доказательствами.

Синтетическое аудио, снимок настроек и отчёт с временем и результатами остаются в `build/speech-verification/packaged-proof/run-*`; тестовый профиль также сохраняется. Существующие профили, авторизация Telegram и модели Ollama не затрагиваются.

Настоящая распакованная Aigram **2.6.39** прошла эту проверку за **44,259 секунды**. Синтез через API занял 10,850 секунды, проверка через настройки и прослушивание — 10,011 секунды. Оба пути создали настоящее Ogg-аудио; плеер настроек загрузил длительность и начал воспроизведение. Перехватчик моделей зафиксировал ноль запросов генерации и ноль неожиданных запросов. Telegram оставался без авторизации и чатов, несохранённые настройки не изменились, а `launch.url` удалился после завершения. Локальное доказательство: `build/speech-verification/packaged-proof/run-KslmQb/proof.json`.

Содержимое локального переносимого EXE после извлечения тоже прошло проверку за **76,760 с**. Хеши исходного EXE и его содержимого сохранены в `build/speech-verification/packaged-proof/run-193EDQ/proof.json`. Отдельно прошли проверки окна, трея и автозапуска Windows. Эти прежние прогоны проверяли локальные сборки.

Настройка не меняет scheduler и не выгружает чужие или резидентные модели Ollama. Ошибки завершённых заданий сохраняют прежний контракт только с текстом: новая панель и причины доступности локализованы, но не у каждой нативной ошибки есть отдельный языковой код очереди.
