# Локальный речевой движок

Aigram использует официальный **Java API sherpa-onnx 1.13.8** для распознавания и синтеза речи на CPU. JNI-движок для Windows x64 и выбранные модели скачиваются отдельно. Открытие приложения и изменение настроек ничего не скачивают. Модели требуют установленный отдельно `sherpa-runtime`: при отсутствии зависимости приложение сообщает об этом, без автоматической установки.

В таблице приведён исторический набор из пяти ресурсов опубликованной **v2.6.41**, включая три исходных голоса. Это не полный нынешний список. Актуальные модели и их условия приведены в [расширенном каталоге](catalog-ru.md).

| ID ресурса | Размер загрузки, байт | Назначение |
| --- | ---: | --- |
| `sherpa-runtime` | 8 277 046 | JNI-движок для Windows x64 CPU |
| `whisper-tiny` | 116 204 861 | Многоязычный Whisper tiny; используются int8 encoder/decoder |
| `piper-ru-irina` | 21 149 417 | Русский голос Ирина |
| `piper-ru-ruslan` | 21 127 907 | Русский голос Руслан |
| `piper-en-amy` | 21 099 246 | Английский голос Amy |

В таблице указан объём загрузки, а не распакованных файлов. Для распознавания доступны автоматическое определение, русский, английский, украинский и казахский языки. Маленький Whisper может ошибаться при распознавании; голос синтеза и модель распознавания выбираются независимо. Аудио не отправляется внешнему речевому сервису.

## Установка и проверка

В версионируемом [каталоге](../../backend/src/main/resources/speech/catalog.json) сохранены точные официальные URL, размеры, SHA-256 и обязательные файлы. Движок поставляется официальным JAR релиза, без большого набора CLI. Загрузка разрешена только по HTTPS с GitHub release hosts, проверяет заявленный размер и SHA-256 до установки.

Архив модели распаковывается во временную папку с уникальным именем. Проверяются выход за пределы папки, абсолютные пути, ссылки и специальные файлы; ограничиваются число элементов и распакованный размер. Сохраняются нужные для работы файлы и исходная карточка модели. Готовая установка публикуется атомарным перемещением папки. Ошибка или отмена не создаёт установленный ресурс. Работает один поток установщика с ограниченной очередью; повторный запрос уже загружаемого ресурса не дублирует работу.

Ресурсы хранятся внутри каталога данных приложения, обычно `%LOCALAPPDATA%/Aigram/speech/<asset-id>`. Маркер установки соответствует закреплённому артефакту. Незавершённые загрузки после перезапуска сами не возобновляются.

## Проверка в настройках и свои голоса

Встроенная проверка настроек ставит в очередь настоящий синтез переданного текста с выбранными голосом и темпом, без сохранения этих предпочтений и вызова чат-модели. Результат — временное Ogg/Opus-аудио через защищённый локальный API, с прослушиванием и отменой. Такую запись нельзя отправить через API голосовых черновиков. Проверка работает без входа в Telegram; для импорта модели нужен текущий авторизованный аккаунт.

Импорт загружает `.tar.bz2` через защищённый локальный API и проверяет архив в отдельной временной папке. Ограничения: 100 МиБ в архиве, 512 МиБ после распаковки и 4096 элементов. Пакет должен содержать одну верхнюю папку, одну ONNX-модель в её корне, `tokens.txt` и обязательные данные eSpeak. Выход за пределы папки, повторяющиеся пути, ссылки, специальные и исполняемые файлы отклоняются. Исходные уведомления модели и уведомления runtime Aigram сохраняются. Для импорта вычисляется локальная SHA-256; в отличие от каталога, закреплённого исходного артефакта у своей модели нет.

Успешный импорт атомарно публикует голос `custom-…` и запись в постоянном локальном реестре. После перезапуска он остаётся в обычном списке озвучивания. Отсутствующие файлы обозначаются как незавершённая локальная установка; автоматического адреса скачивания у своей модели нет. **Обновить список** перечитывает состояние установок, а десктопная кнопка **Проводник** принимает только фиксированный идентификатор папки `speech`. [Поддерживаемый формат пакета](ru.md#проверка-и-импорт-в-настройках).

Ручное окно **Голосовое сообщение** создаёт отдельный черновик, привязанный к беседе. Установленный голос и скорость передаются только для этого запроса, без изменения общих настроек. **Проверить** необязательно: **Озвучить и отправить** ставит синтез в очередь и отправляет результат либо использует готовую неизменённую запись. Закрытие и отмена снимают намерение отправки до её начала. Неопределённую отправку нельзя повторить для той же записи, а после подтверждённой отправки ошибка обновления повторяет только чтение диалога. [Ручная озвучка и черновики ИИ](ru.md#проверка-перед-отправкой).

## Изоляция и приватность

Каждая обработка запускает отдельный JVM-процесс без Spring. Запрос и текст передаются ограниченным UTF-8 JSON через стандартный ввод. В командной строке нет произносимого или распознанного текста. Стандартные вывод и ошибки нативной библиотеки отбрасываются; ответ передаётся через ограниченный временный файл, удаляемый после обработки.

Движок использует CPU, два потока, Java heap 512 МиБ и таймаут десять минут. Нативная библиотека дополнительно выделяет память вне Java heap. Отмена завершает собственный процесс обработки. Входящий WAV остаётся во владении вызывающего кода; возвращённый синтезом WAV интеграция удаляет после преобразования в Opus. Временные файлы протокола очищаются при успехе и ошибке. Содержимое аудио и нативная диагностика не записываются в журнал ошибок приложения. Расшифровки в запросах к модели и текст проверки голоса при авторизованном аккаунте могут сохраняться в приватной локальной истории событий согласно её настройкам хранения и очистки.

Синтез принимает до 4096 единиц UTF-16 и скорость от 0,5 до 2,0. Входящее аудио ограничено 25 МиБ; результат — десятью минутами и 64 МиБ. Кодек преобразует входящие Telegram voice в моно PCM WAV 16 кГц, а синтезированный WAV — в голосовое Ogg/Opus.

## Лицензии и первоисточники

Каталог показывает происхождение лицензии и ограничения конкретного голоса. Скачиваются исходные артефакты авторов; веса моделей не включены в Aigram.

- sherpa-onnx распространяется по [Apache-2.0](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/LICENSE), ONNX Runtime — по MIT. TTS-сборка включает eSpeak NG: [закреплённая зависимость](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/cmake/espeak-ng-for-piper.cmake) ссылается на [фонемизатор GPL-3.0-or-later](https://github.com/csukuangfj/espeak-ng/blob/ed530aa113046142eb5115cf2fc9157854d0ffe1/COPYING).
- Код и веса OpenAI Whisper опубликованы по [MIT](https://github.com/openai/whisper/blob/main/LICENSE).
- Репозиторий голосов Piper использует MIT, но важны сведения о конкретном наборе данных: [карточка Ирины](https://huggingface.co/rhasspy/piper-voices/blob/main/ru/ru_RU/irina/medium/MODEL_CARD) не уточняет лицензию датасета, [карточка Руслана](https://huggingface.co/rhasspy/piper-voices/blob/main/ru/ru_RU/ruslan/medium/MODEL_CARD) указывает CC-BY-NC-SA-4.0, [карточка Amy](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/amy/low/MODEL_CARD) отсылает к исходному Mimic3. Архивы голосов также включают данные eSpeak NG.
- [Официальный пример Java-интеграции](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/java-api-examples/gradle-examples/build.gradle) разделяет небольшую JVM-библиотеку API и платформенные нативные JAR.

## Проверка

Unit- и HTTP-регрессии исходного речевого релиза проверяют размер и контрольную сумму, защиту распаковки от обхода пути и ссылок, состояние установки, отмену, запуск без сети, выбор моделей, точный Unicode-текст для синтеза, очистку файлов протокола, разделение проверки и отправки и сохранение импортированной модели. Его финальный Gradle gate завершён: 619 Kotlin-сценариев, ноль ошибок и 14 пропусков — 12 несвязанных добровольных проверок ИИ/сети/памяти и две проверки прав на символьные ссылки Windows. Прошли 12 тестов установленного SDK, полный набор из 257 UI-тестов, 39 Electron-тестов и 10 тестов скриптов. Дополнительный точечный прогон проверил 16 тестов в четырёх файлах, включая три новые регрессии хука. Это исторические результаты исходной версии. Новые локальные результаты расширенного каталога записаны в основном руководстве речи; публикация проверяется отдельно.

Настоящие тесты включаются явно через `AIGRAM_LIVE_SPEECH=true` и используют ранее скачанные артефакты из `build/speech-verification`. Прошли следующие изолированные проверки:

| Проверка | Настоящая обработка | Время |
| --- | --- | ---: |
| `LiveSpeechSettingsTest` | Загрузка настоящего архива Piper размером 21 МБ через HTTP, импорт, озвучивание введённого текста и получение Ogg-аудио для прослушивания | 15,782 с |
| `LiveSpeechPipelineTest` | Проверяемая установка → русский синтез Piper → Ogg/Opus → моно WAV 16 кГц → распознавание Whisper | 36,130 с |
| `LiveSpeechVoicesTest` | Установка и синтез трёх исходных голосов каталога: Ирина, Руслан и Amy | 34,490 с |

В прогоне трёх исходных голосов установка заняла 14 866 мс, синтез Ирины — 3886 мс, Руслана — 3673 мс, Amy — 5994 мс. Прежняя непостоянная ошибка установки Руслана не повторилась в отдельной и финальной проверках трёх голосов; её причина не установлена. Тестовая диагностика фиксирует ошибки установки без изменения production-поведения.

Цикл сохранил произнесённые слова; пунктуацию Whisper восстанавливает сам, поэтому её точное совпадение не требуется. Общее время тестов включает подготовку и очистку, а не только работу модели, и зависит от проверочной машины. Проверки не обращаются к Telegram, не используют настоящий профиль приложения и не меняют модели Ollama. Полный браузерный прогон исходного релиза проверил 135 сценариев; после его правок сворачиваемого заголовка и хука прошли все восемь голосовых сценариев (`build/speech-browser-last.log`). Эти числа не относятся к новому каталогу и ручному окну. Браузерные фикстуры отдельно проверяют управление; проверка EXE ниже также использует настоящий синтез и прослушивание.

## Отдельная проверка упакованного приложения

Эта явно запускаемая Windows-проверка использует настоящие встроенные JVM, речевой процесс и кодек. Она не входит в обычный набор тестов и ничего не скачивает. Сначала установите npm-зависимости проекта и положите закреплённые каталогом `sherpa-onnx-native-lib-win-x64-1.13.8.jar` и `vits-piper-ru_RU-irina-medium-int8.tar.bz2` в `build/speech-verification`. Из корня репозитория выберите распакованную сборку или скачанный portable EXE:

```powershell
$env:AIGRAM_TEST_EXECUTABLE = (Resolve-Path '.\complie\win-unpacked\Aigram.exe').Path
npm --prefix desktop run test:speech

# Для проверки скачанного релиза:
$env:AIGRAM_TEST_EXECUTABLE = 'C:\Downloads\Aigram.exe'
npm --prefix desktop run test:speech
```

Старое имя `BOLTUNYA_TEST_EXECUTABLE` также поддерживается; без обоих переопределений используется `complie/win-unpacked/Aigram.exe`. Скрипт проверяет размеры и SHA-256 исходных файлов, создаёт новый `build/speech-verification/packaged-profile-*` и запускает приложение без Telegram-аккаунта и проверки обновлений. Он вызывает настоящий API проверки, запускает озвучивание и прослушивание в настройках, проверяет отсутствие запросов генерации через локальный перехватчик Ollama, закрывает своё приложение и проверяет удаление `launch.url`.

Для portable EXE скрипт использует установленный Windows 7-Zip: извлекает только фиксированный NSIS payload `$PLUGINSDIR/app-64.7z`, затем распаковывает приложение в новый `build/speech-verification/packaged-extract-*`. Проверяет наличие `Aigram.exe` и `resources/app.asar` и запускает извлечённое приложение; отладчик не подключается к оболочке NSIS. Уже распакованный EXE с соседним `resources/app.asar` запускается напрямую. В отчёт попадают SHA-256 исходного EXE и запускаемого EXE payload, а `portablePayloadExtracted` указывает выбранный путь. Папка распаковки сохраняется вместе с остальными синтетическими доказательствами.

Синтетическое аудио, снимок настроек и отчёт с временем и результатами остаются в `build/speech-verification/packaged-proof/run-*`; тестовый профиль также сохраняется. Существующие профили, авторизация Telegram и модели Ollama не затрагиваются.

Настоящая распакованная Aigram **2.6.39** прошла эту проверку за **44,259 секунды**. Синтез через API занял 10,850 секунды, проверка через настройки и прослушивание — 10,011 секунды. Оба пути создали настоящее Ogg-аудио; плеер настроек загрузил длительность и начал воспроизведение. Перехватчик моделей зафиксировал ноль запросов генерации и ноль неожиданных запросов. Telegram оставался без авторизации и чатов, несохранённые настройки не изменились, а `launch.url` удалился после завершения. Локальное доказательство: `build/speech-verification/packaged-proof/run-KslmQb/proof.json`.

Содержимое локального переносимого EXE после извлечения тоже прошло проверку за **76,760 с**. Хеши исходного EXE и его содержимого сохранены в `build/speech-verification/packaged-proof/run-193EDQ/proof.json`. Отдельно прошли проверки окна, трея и автозапуска Windows. Эти прежние прогоны проверяли локальные сборки.

### Проверка опубликованной v2.6.41

Опубликованный [релиз v2.6.41](https://github.com/kreeeeeel/boltunya/releases/tag/v2.6.41) прошёл [Windows CI](https://github.com/kreeeeeel/boltunya/actions/runs/39668438423). Тег и исходный коммит совпадают: `159228cc30f4fca063e9ddad0cd59b4a244a5b58`; хеши скачанных EXE и SDK сверены с опубликованными значениями. Размер скачанного portable EXE — 267 083 244 байт, SHA-256 `a3ecb4870f6d981f8e8df967d0791293809b3a77c8caa14fdb0b69f5625e679f`.

Именно содержимое скачанного приложения прошло настоящую проверку речи за **34,822 с**: синтез через API занял 4,743 с, синтез и прослушивание через настройки — 4,417 с. Настоящее аудио воспроизводилось в новом профиле без входа в Telegram; запросов к чат-модели и неожиданных обращений к моделям не было. Несохранённые голос и скорость остались неизменными, после завершения удалился дескриптор сессии. Доказательство: `build/speech-verification/packaged-proof/run-V0O1bt/proof.json`.

После этого опубликованный portable EXE запущен обычным способом с существующим профилем: обновление **2.6.38 → 2.6.41** сохранило авторизацию Telegram, настройки и ручные заметки памяти. Отчёт с безопасными статусами — `build/aigram-2.6.41-published-restart.json`, общие результаты — в локальном `complie/VERIFICATION.md`. Это подтверждает опубликованную исходную версию, а не расширенный каталог и новое ручное окно: их новые локальные результаты приведены в основном руководстве речи.
