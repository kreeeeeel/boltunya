# Внедрение зависимостей

Базовый пакет Kotlin: `ru.aigram`. Исходники и тесты находятся в модуле `backend`.

Spring Boot 4.1.1 управляет singleton-компонентами с внедрением через конструкторы. `Main` передаёт конфигурацию запуска, открывает контекст и явно запускает `ApplicationRuntime`. `AigramApplication` сканирует компоненты. Конфигурации по функциям предоставляют внешние клиенты, callback-интеграции и ресурсы через `@Bean`. Сервисы не запрашивают контейнер. Guice и его модуль удалены.

Отложенные Jakarta `Provider<T>` сохраняют ленивую связь между обновлениями Telegram, ответами и памятью. Внедрение интерфейсов использует один экземпляр реализации: координатор ответов также является общей очередью памяти, оба интерфейса суммаризации разделяют один сервис. Собственного контейнера и service locator нет.

`ApplicationRuntime` владеет блокировкой профиля и порядком запуска/закрытия служб. Spring закрывает runtime при завершении контекста; повторное закрытие его служб безопасно благодаря идемпотентности. Если создание контекста прерывается до появления runtime, Spring освобождает уже созданные ресурсы. Создание контекста не авторизует Telegram, не запускает мониторинг и генерацию. Профиль `%LOCALAPPDATA%/Aigram` и существующие сессии сохранены.

Проверка: `gradlew.bat :backend:check`. Тесты Spring-контекста разрешают граф, проверяют общие экземпляры, ленивое внедрение, сохранённый автозапуск и повторное закрытие без отправки сообщений или обращения к модели. Встроенный runtime содержит `java.instrument` и проверяется изолированными нативными сценариями Electron.

Оболочка остаётся в `desktop`, интерфейс — в `web`. `scripts/build.ps1` создаёт `complie/Aigram.exe`. Старый HTTP-мост остаётся временно до следующего [этапа contract-first миграции](../migration/ru.md).
