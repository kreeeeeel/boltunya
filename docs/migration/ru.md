# Миграция на Spring

Сохраняются Electron, статический интерфейс Next.js, переносимый EXE и профиль JSON/Markdown. Spring выбран для бэкенда; добавлять базу данных ради миграции не требуется.

## Следующий этап — генерация контрактов

1. Зафиксировать действующие operationId, методы, URL, JSON-форматы и проверки защиты локального API.
   Сейчас в источнике 59 путей, 73 операции и 78 схем. У трёх операций нет operationId (`GET`/`PUT /api/model-prompts`, `POST /api/prompts/budget`), у 38 нет tags. До генерации сверить реальные payload, ответы media с диапазонами и ошибки.
2. Разделить единый OpenAPI на операции по функциям и отдельные файлы моделей. Внутри `backend` добавить Gradle-модули серверного контракта, Kotlin-клиента, полноценного TypeScript HTTP-клиента и рукописной клиентской обёртки. Исполняемый модуль переносить после согласованного переключения потребителей.
3. Генерировать Kotlin Spring API/DTO, Kotlin WebClient и TypeScript-клиент в `build/generated`: сначала валидация ссылок, затем очистка устаревших результатов и генерация, затем компиляция. Проверить чистый checkout.
4. Добавить Spring MVC-контроллеры, transformer по функциям, Jakarta Validation и единый обработчик ошибок. Сохранить лимиты загрузок, статические ресурсы, медиа, loopback-привязку и проверки сессии/Host/Origin.
5. Переключить веб, Electron и сборку; проверить совместимость и нативный запуск/обновление. После этого полностью удалить `ru.aigram.http`, старые сервер, router, обработчики и ненужные зависимости. Временный HTTP-мост не считается завершённой миграцией.

## Затем — функциональные пакеты и очистка

Разбирать плоские domain/storage/service-пакеты по функциям (`chat`, `media`, `memory`, `ai`, `settings`, `events`). Domain отделять от generated DTO. В затронутых областях приводить условия к многострочным блокам со скобками, отделять смысловые шаги методов, сохранять один класс в файле и Java Stream API. Удалять заменённый код, дубли моделей, устаревшие импорты и адаптеры после проверки потребителей.

## Проверки

`:backend:check`, валидация и чистая генерация контрактов после их появления, проверки веба/Electron, браузерные сценарии и изолированные нативные тесты окна, трея, обновлятора и медиа. Проверять блокировку профиля, запуск/закрытие контекста, общую очередь, интервалы памяти и защиту API. Сохранять авторизацию и заметки; не отправлять сообщения людям и не скачивать модели ради тестов. Каждый релиз: changelog, успешный Windows CI, соответствующий исходному коммиту тег и совпадающий SHA-256 EXE.
