# Интернет-поиск и ссылки

## Получение данных

В параметрах общения включается **Поиск в интернете**. Обычные личные разговоры, реакции и вопросы о времени компьютера обходятся без поискового запроса. Для погоды, новостей, цен, курсов и явных просьб найти сведения локальная модель составляет короткий запрос. Уточнение вроде «а завтра?» использует недавнюю тему; случайная старая тема не должна запускать поиск.

Погода запрашивается через Open-Meteo. Если город неизвестен, помощник уточняет его. Общий поиск по умолчанию использует DuckDuckGo и резервную RSS-выдачу Bing: ключи, подписка, Node.js, отдельный MCP-процесс и Docker не нужны.

Exa — необязательный дополнительный резерв. Приложение обращается к ней только после неудачного бесплатного поиска и только при сохранённом собственном ключе. Без ключа запросов к Exa нет. Интеграция использует официальный MCP Java SDK и только инструмент web_search_exa. Доступность внешних поисковиков может меняться: при недоступности обоих помощник сообщает, что не удалось проверить сведения.

Из выдачи удаляются поисковые страницы, неподходящие темы и дубли с рекламными параметрами. Отбираются до трёх источников, максимум два с одного сайта. Слова запроса сопоставляются с заголовком и содержимым; словари содержат общие слова и соответствия вроде «доллар» → USD. До двух страниц читаются параллельно, после чего результаты повторно проверяются по теме. Ошибка чтения оставляет доступный поисковый фрагмент. Результат кешируется на две минуты; неудачный запрос в кеш не закрепляется.

В промпте сохраняются дата получения и известная дата публикации. Модель должна отличать старые новости, стабильные версии и будущие планы, а при недостатке данных говорить, что сведения подтвердить не удалось. Внешние тексты помечены как недоверенные данные. Это улучшает выбор фактов, но не превращает ответ модели в гарантированно точную проверку каждого утверждения.

## Когда отправляются ссылки

Параметры общения → **Настроить общение** → **Ссылки в ответах**:

- **Когда собеседник просит** — по умолчанию. Обычный ответ о погоде или новостях не получает случайный URL.
- **Всегда при использовании поиска** — добавляет найденный источник, если модель не включила подходящий URL сама.
- **Не отправлять** — убирает ссылки из ответов, использующих внешние данные.

В режиме по просьбе учитываются запросы источника на русском, английском, казахском и украинском. «Без ссылок» не считается просьбой дать ссылку. Во внешнем контексте ссылки скрываются, когда они не нужны. После генерации отдельная проверка разрешает только адреса отобранных источников и убирает выдуманные URL и сноски. Прежнее безусловное добавление первого результата удалено. Обычные ссылки из личного разговора, в котором поиск не использовался, этим правилом не переписываются.

## Собственный ключ

Профиль → **Настройки** → **Интернет-поиск** → **Дополнительно: резервный поиск Exa** показывает состояние Exa и наличие сохранённого ключа. **Получить ключ Exa** открывает [панель Exa](https://dashboard.exa.ai/api-keys). Введите ключ и нажмите **Сохранить ключ**. Он применяется сразу, независимо от сохранения остальных настроек. Поле очищается после успешного сохранения. **Удалить ключ** отключает дополнительный резерв Exa. Основной бесплатный поиск продолжает работать.

Ключ хранится в `%LOCALAPPDATA%/Tiho/search.credentials`, зашифрованном Windows DPAPI, и передаётся Exa в заголовке `x-api-key`. Он не записывается в `settings.json`, не возвращается через API и не включается в журналы. **Проверить подключение** выполняет один фиксированный публичный запрос из ресурсов; переписка для проверки не используется.

Локальная модель обрабатывает переписку на компьютере. Поисковому сервису передаётся сформированный запрос до 180 символов, погодному — город; полная история и Telegram-ключи туда не отправляются. Встроенная проверка блокирует запросы с распознанными номерами и адресами электронной почты. Открытие публичных страниц использует существующую защиту от локальных адресов и проверяет переходы.

## Контракт и расширение

- `GET /api/search/connection` — только `configured` и состояние `unchecked`, `ready`, `limited` или `unavailable`.
- `POST /api/search/connection` — сохранение `apiKey`.
- `DELETE /api/search/connection` — удаление ключа.
- `POST /api/search/check` — проверка соединения.
- `ChatRule.sourceLinks` — `requested`, `always`, `never`. Старые правила получают `requested`.

Защита локальной сессией и Host/Origin применяется ко всем маршрутам. Промпты находятся в `resources/prompts/ru/research`, regex — в `resources/patterns`, стоп-слова — в `resources/search/stopwords/<language>.json`, соответствия — в `resources/search/aliases.json`. Новый язык добавляется через существующий `languages.json` и соответствующие языковые файлы.

Проверки покрывают MCP handshake и SSE-ответы, служебный ответ об исчерпании лимита, резервный поиск и задержку повторов, смену ключа, DPAPI и отсутствие ключа в API, сортировку и дубли, режимы ссылок, настройки чата и обработку ошибок интерфейса. Браузерные тесты используют подставные API; необязательная проверка с Ollama использует искусственную переписку.


## Проверенные курсы, новости и уточнения

Вопросы об обычном официальном курсе обрабатываются через XML Банка России, с запросом на текущую дату и явной датой действия в ответе. Номинал валюты учитывается: котировка за 100 единиц переводится в курс за одну. Поддерживаются USD, EUR, RUB, KZT, UAH, CNY и GBP, а также пересчёт пары. Официальный курс отличается от биржевого и наличного: запросы о покупке, продаже и прогнозах остаются задачами общего поиска. Источник — [описание XML-сервиса ЦБ](https://www.cbr.ru/development/SXML/).

Обычные новости берутся из публичных RSS РБК и ТАСС. Сохраняется дата публикации, отбрасываются записи старше 36 часов, без даты и с датой из будущего. Для запроса «сегодня» используется текущая календарная дата. Подборка различает Россию и мировые новости; темы фильтруются по доступным заголовкам и описаниям. Если подтверждённого материала нет, приложение сообщает об этом и не генерирует события или котировки из памяти модели.

Последний успешный поисковый запрос хранится отдельно для каждого диалога до десяти минут. Соседние просьбы «дай ссылку» и «подробнее» повторно используют эту проверенную тему и кратковременный кеш данных, вместо нового поиска по случайному заголовку из ответа. Смена темы прерывает такое продолжение. После «а завтра?» уточнение «а в Казани?» сохраняет дату прогноза, пока пользователь явно не изменит её. «А евро?» после курса доллара вызывает получение курса EUR.

Живые тесты запускаются с TIHO_LIVE_INTERNET=true, используют установленную Gemma 3 4B и публичные тестовые вопросы, ничего не отправляя в Telegram. Отчёт: backend/build/reports/live-research-conversations.json. Он содержит вопросы, ответы, запросы и источники; значения USD/EUR проверяются независимым чтением XML ЦБ. Дополнительно проверяются ссылки, свежесть публикаций и дата прогноза в уточнениях.
