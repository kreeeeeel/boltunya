# Вложения, кеш и удалённые сообщения

## Автозагрузка

Профиль → **Настройки** → **Автозагрузка**: фотографии, видео/GIF, аудио/голосовые и документы включаются отдельно. По умолчанию загружаются фотографии до 20 МБ; остальные категории выключены. Лимит применяется к каждому файлу. Интерфейс предлагает 5, 10, 20, 50 и 100 МБ; API принимает целое число от 1 до 100.

Новые вложения поступают в последовательную фоновую очередь максимум из 64 файлов. Перед загрузкой повторно проверяются текущие настройки. Для истории разрешение проверяется при показе сообщения. Выключенная автозагрузка оставляет кнопку **Загрузить**; уже сохранённый файл можно смотреть независимо от переключателя. Ручная загрузка ограничена 100 МБ. Аватары, обои, стикеры и миниатюры используют существующий механизм отображения и не относятся к этим четырём переключателям.

## Медиакеш

В настройках показаны размер, число файлов и разбивка по фото, видео, аудио и документам. Кнопка обновления запрашивает текущие данные TDLib. **Очистить медиакеш** удаляет скачанные вложения через `optimizeStorage`, после чего интерфейс показывает фактически оставшийся размер. Используемые или защищённые TDLib файлы могут остаться.

Размер относится к файлам Telegram; модели Ollama, исполняемые файлы, база Telegram, настройки, память и локальная история сообщений сюда не входят. Очистка не выходит из аккаунта и не удаляет текст сохранённых сообщений. Открытые разрешённые вложения могут загрузиться заново при следующем обращении. Для остановки повторной загрузки отключите соответствующую категорию.

В запросе очистки явно перечисляются обнаруженные типы файлов, включая аватары, стикеры, обои и миниатюры: стандартный набор TDLib не включает их все. Семантика операции описана в [документации TDLib](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1optimize_storage.html).

## Сохранение удалённых сообщений

Приложение сохраняет локальные копии полученных сообщений и прочитанных страниц истории. Постоянное удаление, о котором сообщил Telegram, помечает известное сообщение как **Удалено**. Текст, форматирование, исходная дата и сведения о вложении остаются в ленте. Кнопка **Удалённые сообщения** в параметрах общения открывает отдельный список удалённых сообщений с подгрузкой истории.

Восстановить содержимое, которое приложение не успело получить, нельзя. Удаление должно быть получено как событие Telegram; приложение не пытается угадывать его по отсутствию сообщения в странице истории. Временное удаление и вытеснение из кеша TDLib не помечаются как удаление собеседником; различие флагов описано в [updateDeleteMessages](https://core.telegram.org/tdlib/docs/classtd_1_1td__api_1_1update_delete_messages.html).

Фотография или другое удалённое вложение доступны, пока Telegram ещё отдаёт файл либо он остаётся в локальном медиакеше. Очистка кеша может убрать последнюю доступную копию такого вложения; текст и отметка удаления сохраняются. Проверка стабильного идентификатора файла запрещает показывать другое вложение при повторном использовании числового ID новой Telegram-сессией.

Файлы находятся в `%LOCALAPPDATA%/Tiho/history/<accountId>/<chatId>/`: порции сообщений — отдельные JSON-файлы, постоянные отметки удаления — `deleted.json`. Запись атомарная, аккаунты разделены. Папка содержит переписку и не должна передаваться другим людям. Автоматического ограничения размера текстового архива пока нет.

Удаление сообщения отменяет ожидающий ответ на него. Архив удалённых сообщений предназначен для просмотра; его содержимое не добавляется к истории, передаваемой модели. Уже созданные до удаления сводки памяти обновляются отдельно.

## API и проверки

Контракт — `backend/contract/api.yaml`. Все маршруты используют существующую локальную авторизацию и проверку Host/Origin:

- `GET /api/cache` — текущая статистика.
- `POST /api/cache/clear` — очистка и оставшаяся статистика.
- `POST /api/media/{fileId}/download` — явная загрузка известного вложения.
- `GET /api/chats/{chatId}/deleted?before=<messageId>` — страница удалённых сообщений. ID передаётся строкой без потери точности.
- `PATCH /api/settings` — `autoDownloadPhotos`, `autoDownloadVideos`, `autoDownloadAudio`, `autoDownloadFiles`, `autoDownloadMaxMb`.

Тесты проверяют категории и лимиты загрузки, последовательную очередь, явное получение медиа, очистку с фактическим остатком, защиту API, сохранение текста и форматирования после перезапуска, изоляцию аккаунтов, пагинацию, различие постоянного удаления и очистки кеша, конфликт идентификаторов вложений и отмену ответа на удалённое сообщение. Браузерные сценарии используют подставные ответы API; реальная переписка и пользовательский кеш не изменяются.

## Локальные файлы и журнал ошибок

Откройте **Настройки → Расположение файлов**, чтобы увидеть папки, используемые запущенным приложением. Кнопка **Открыть в Проводнике** доступна для существующих локальных папок. Electron получает идентификатор расположения и заново проверяет список разрешённых путей на бэкенде; веб-интерфейс не может передать произвольный путь.

| Расположение | Содержимое |
| --- | --- |
| Данные приложения | Настройки, сессия Telegram, стили и локальные хранилища. Профиль Windows по умолчанию — `%LOCALAPPDATA%\Tiho`; явно заданная папка профиля имеет приоритет. |
| Память | `memory/MEMORY.md` содержит общие заметки и автоматически собранный профиль владельца. Документы бесед находятся в `memory/<account-id>/<chat-id>/MEMORY.md`; рядом сохраняются состояние сбора и сводки владельца. |
| Файлы Telegram | Папка `telegram` содержит данные TDLib и загруженные медиа. Для удаления медиа используйте очистку кэша, не удаляйте файлы сессии вручную. |
| Движок Ollama | Папка исполняемого файла встроенной или обнаруженной локальной установки Ollama. |
| Модели Ollama | `OLLAMA_MODELS`, если переменная задана, либо `.ollama/models` текущего пользователя для обнаруженной локальной установки. Внешняя служба может использовать другую папку. |
| Журнал ошибок | `diagnostics/errors.json` — ограниченный журнал поддержки, до 100 сгруппированных ошибок. |

Docker, служба другого пользователя и удалённая Ollama могут использовать хранилище, недоступное приложению. Такие расположения показаны как внешние: без выдуманного пути на компьютере и кнопки открытия. Эта страница не переносит файлы и не скачивает модели.

Страница **«Ошибки»** собирает сбои автоответов, скачивания и прогрева моделей, операций памяти, запросов к приложению и обновлятора. Ошибки с одинаковыми источником, кодом и типом исключения объединяются в карточку со счётчиком. Карточка содержит время, понятное объяснение, рекомендации и технические сведения. История сохраняется между запусками; её можно очистить.

В журнал не попадают сообщения исключений, тексты Telegram, идентификаторы аккаунтов и бесед, промпты и ключи. Технические поля ограничены HTTP-статусом, типами исключений, местами вызовов в коде приложения и этапом обновления. Сырые логи и полная история генерации не включаются. Ошибки обновлятора импортируются из фиксированного файла `desktop/updates/last-error.json`; очистка истории удаляет и эту исходную запись.

Локальный API с авторизацией описан в [OpenAPI-контракте](../../backend/contract/api.yaml):

- `GET /api/storage/locations` — папки, их доступность и возможность открытия в Проводнике.
- `GET /api/diagnostics/errors` — безопасные сгруппированные ошибки с подробностями.
- `DELETE /api/diagnostics/errors` — очистка журнала поддержки.

Эти маршруты требуют cookie локальной сессии приложения и не открывают публичный сетевой сервис. Для отдельного отчёта об установленных моделях и необязательной проверки генерации используйте [диагностический скрипт Windows](../diagnostics/ru.md).
