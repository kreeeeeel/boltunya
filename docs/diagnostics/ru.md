# Диагностика ИИ на Windows

Сначала откройте страницу **«Ошибки»** в приложении. Нажатие на карточку показывает объяснение, рекомендации и технические сведения; повторяющиеся ошибки объединяются со счётчиком. Раздел расположения файлов в настройках открывает папку диагностики в Проводнике. Журнал ограничен по размеру и не содержит переписок, ключей или промптов.

Для отдельного отчёта о доступности приложения, Ollama и моделей используйте следующие шаги:

1. Откройте Aigram. На странице моделей убедитесь, что Ollama работает и модель скачана. Если проверка скорости работает, а автоответов нет, проверьте запуск ИИ, разрешение ответов в нужном диалоге и паузу очереди на странице событий.
2. Скачайте `Diagnose-AI.ps1` из того же релиза, что и приложение. Откройте PowerShell в папке загрузки и выполните:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Diagnose-AI.ps1 -TestModel
   ```

3. Отправьте разработчику файл `aigram-diagnostics.json` с рабочего стола, название модели и текст ошибки из карточки события. Не отправляйте папку профиля, `launch.url`, ключи Telegram, файлы памяти или полную историю события.

Скрипт не скачивает модели, не меняет настройки и не отправляет сообщения в Telegram. Флаг `-TestModel` запускает предпросмотр короткого тестового ответа на модели по умолчанию без истории беседы, памяти, адаптации манеры и интернет-поиска. Проверка может занять до трёх минут; она измеряет работоспособность генерации, а не качество переписки. В отчёт попадают только статус, время и скорость генерации. Текст тестового ответа не сохраняется. Без флага генерация не запускается.

По умолчанию диагностика читает Aigram; если его `launch.url` отсутствует, а старый Tiho ещё используется после обновления, скрипт читает Tiho без переноса файлов. Явный `-DataDirectory` и переменные папки профиля сохраняют приоритет.

Отчёт содержит версии, доступность Ollama, названия установленных моделей, объём памяти, модель видеокарты, количество включённых диалогов, состояние очереди и фазы последних задач. В нём нет имён контактов, идентификаторов бесед, ключей, промптов, переписок и сырых логов. Глобальные инструкции приложения могут влиять на предпросмотр, но в отчёт не включаются.

Поле `generation.requestDurationMs` измеряет ожидание запроса даже при ошибке. Вместе со статусом оно помогает отличить немедленный отказ соединения от долгой генерации или истечения времени ожидания; само по себе оно не определяет причину сбоя.

| Поле или код | Что проверить |
| --- | --- |
| `APPLICATION_UNREACHABLE` | Приложение должно быть запущено. Для нестандартного профиля укажите `-DataDirectory 'C:\path\to\profile'`. |
| `OLLAMA_OFFLINE` | Запустите Ollama из страницы моделей. Если запуск не получается, нужны текст ошибки и версия приложения. |
| `DEFAULT_MODEL_NOT_INSTALLED` | Выберите скачанную модель. Проверяйте также отдельную модель в параметрах проблемного диалога. |
| `AI_PAUSED`, `QUEUE_PAUSED`, `NO_ENABLED_CHATS` | Включите ИИ, снимите паузу очереди и разрешите ответы в нужном диалоге. |
| `DEFAULT_MODEL_DRAFTS_ONLY` | Модель доступна для предпросмотра, но не автоматической отправки. |
| `MODEL_EXCEEDS_SYSTEM_MEMORY_ESTIMATE` | Требования модели выше объёма памяти компьютера. Попробуйте меньшую модель; это предварительная оценка, а не точный диагноз. |
| `generation.status = OK` | Локальная генерация работает. Для автоответов проверяйте правила диалога, очередь, групповой режим и фильтр заданий помощнику. |
| `ENGINE_UNAVAILABLE`, `HTTP_ERROR` | Нужны код ошибки, HTTP-статус и состояние Ollama. Возможные причины различаются: остановка сервера, нехватка памяти или ошибка загрузки модели. |
| `EMPTY_MODEL_REPLY`, `INVALID_MODEL_REPLY`, `EMPTY_REPLY` | Ошибка генерации или проверки ответа. Укажите точный тег модели и версию приложения. |

В группах ответы по умолчанию выключены. Режим «Только упоминания» отвечает лишь на упоминание владельца. Фильтр заданий помощнику может пропускать рецепты и подобные команды без генерации. Индивидуальный выбор модели в диалоге может отличаться от модели по умолчанию — отчёт показывает количество таких переопределений, не раскрывая сами беседы.

Пример запуска из исходников с отдельным расположением отчёта:

```powershell
./scripts/diagnose-ai.ps1 -OutputPath './build/friend-diagnostics.json' -TestModel
```

Регрессионные проверки скрипта выполняются на синтетическом локальном сервере, проверяют исключение приватных данных, передачу локальной авторизации, ошибки генерации и запрет отправки cookie на внешний адрес:

```powershell
node.exe --test scripts/tests/diagnose-ai.test.cjs
```
